## 2. 內建品項快照

  - **建檔步驟（建置前一次性，不在 build 時打網路）**：`scripts/fetch-fam-details.mjs` 逐項抓明細，限速（每秒 ≤2 次）、可續跑，結果存 `/workspace/food-research/fam_details.jsonl`。快照只讀這個檔。抓不到明細的品項當成「要補營養素」處理（同 7-11）。這一步由 Karina／Ningning 在 build 前跑，coding agent 不要自己打全家的 API。
- 7-11：`711_0.xml` … `711_21.xml`（`<Item>` 下有 `name`、`kcal`、`price`、`content`），約 702 項，只有熱量；`kcal` 空白的品項**不收**。
- 衛福部資料（`fda*`）v1 不用。

### 2.2 快照格式 `public/catalog-v1.json`
```json
{ "version": "2026-10-10", "items": [
  { "id": "fm:1032099", "src": "familymart", "name": "法式香草嫩雞胸", "cat": "小菜、滷味、湯品",
    "serving": "1 份（100 g）", "servingG": 100, "perPack": 1,
    "kcal": 106, "protein": 20.8, "fat": 1.5, "carb": 2.3 },
  { "id": "711:<sha1(name)前 10 碼>", "src": "711", "name": "晶英-麻辣奶油鮮蝦義大利麵", "cat": "鮮食",
    "serving": "1 份", "servingG": null, "kcal": 586, "protein": null, "fat": null, "carb": null }
]}
```
- 營養素是**每份**；`servingG` 有值時才能用克數記。`null` = 缺，搜尋列標「要補營養素」。
- id 穩定：全家用 `CMNO`，7-11 用名稱雜湊（同名去重，取第一筆）。
- 快照由 Service Worker 預快取（`globPatterns` 包含 `catalog-*.json`），離線可用。檔名帶版本，更新時改名。

### 2.3 自建與補填（Sheet `Items`）
- 自建品項（App 手動或 Kyujin）：`id = "u:<uuid>"`。
- 補填官方品項的營養素：存一列 `id = "ov:<官方 id>"`、`base_id = <官方 id>`，四項營養素完整。合併時，有 override 的官方品項用 override 的數字，標籤「要補營養素」消失。**不改快照、不改官方資料。**

## 3. 本機搜尋（驗收 10：5,000 項，每打一字 <100 ms，離線）
- 啟動時建索引（在 `requestIdleCallback` 或 Web Worker，不擋首頁渲染）：每項存 `norm(name + cat + 品牌前綴)`，`norm` = NFKC、轉小寫、全形轉半形、去空白和標點（`-`、`·`、`（）`）。
- 比對（依序計分，取前 50 筆）：
  1. 完全包含整個查詢字串（子字串）：100 分；在開頭再 +20。
  2. 查詢的每個字元依序出現（subsequence，例「雞肉」可以命中「雞胸肉」；順序不同不算）：60 分。
  3. 容錯：查詢長度 ≥3 時，用字元 bigram 重疊率 ≥0.5：40 × 重疊率。
- 加權：收藏 +50、最近 14 天吃過 +30（再依次數 +2/次，上限 +20）、自建 +10。篩選膠囊：全部／收藏／7-11／全家。
- 分組照 DESIGN §6.5：「收藏・最近吃過」（含自建）在前，「7-11・全家」在後。
- 每次輸入不 debounce（直接算），但用 `useDeferredValue` 讓輸入框不卡。
- 效能測試：`test/search.perf.test.ts` 產生 5,000 個中文品名，測 1–4 字查詢各 50 次，p95 < 30 ms（Node，留給手機 3 倍餘裕）。

## 4. Sheet 分頁（`gas/Schema.gs`）
所有紀錄類分頁共同欄位：`id`、`ts`（ISO 字串含 `+08:00`）、`deleted`（TRUE/FALSE）、`updated_at`。欄位值人看得懂。**不要改既有欄位名稱或順序**，加欄位只能加在最後。

| 分頁 | 主鍵 | 欄位 |
|---|---|---|
| `Items` | `id` | `id`, `ts`, `deleted`, `updated_at`, `kind`（`自建`／`補填`）, `base_id`, `src`（`7-11`／`全家`／`其他`）, `name`, `serving`, `serving_g`, `kcal`, `protein`, `fat`, `carb`, `fav`（TRUE/FALSE）, `created_by`（`app`／`kyujin`） |
| `Logs` | `id` | `id`, `ts`（吃的時間）, `deleted`, `updated_at`, `day`（台北日期 `YYYY-MM-DD`）, `item_id`, `name`（快照當下的品名）, `src`, `qty`（份數）, `grams`（用克數時才有）, `kcal`, `protein`, `fat`, `carb`（**這筆實際吃的量**，已換算） |
| `Weights` | `day` | `day`（`YYYY-MM-DD`）, `ts`, `deleted`, `updated_at`, `kg`, `id` |
| `Config` | `key` | `key`, `value`, `updated_at` |

- 收藏官方品項：存在 Config key `fav_ids`（逗號分隔的官方 id），不寫 Items（避免被當成補填）。自建品項用自己的 `fav` 欄。
- Config 預設：`target_kcal=2000`、`target_protein=150`、`target_fat=60`、`target_carb=200`、`tdee=`（空）、`remind_meal_times=`（例 `12:00,19:00`）、`remind_weight_time=`、`theme`（只存前端 localStorage，不進 Sheet）。`defaults.ts` 和 `Schema.gs` 必須一致（測試比對）。
- Logs 存換算後的數字（不是只存 item_id），所以官方快照更新或品項被改，舊紀錄不變；Kyujin 直接加總 Logs 就和 App 一致。

### 4.1 每筆紀錄四項營養素都要有（PRD 不可存在只有熱量的紀錄）
- 前端：`PortionSheet` 在品項缺任一營養素時先進補營養素步驟；三欄都是 ≥0 的數字才能下一步。按「記錄」時，**先**把 `ov:` 補填（或自建品項更新）放進 outbox，**再**放 Log，順序送出。
- 後端：`append Logs` 時驗證 `kcal/protein/fat/carb` 四個都是有限數字且 ≥0，否則回 `bad_record`。`upsertItem` 同樣驗證四項。
- 中途關掉 Sheet：不寫任何東西（補填也不寫）。
- 測試：codec、後端驗證、PortionSheet 的「下一步」停用狀態。

### 4.2 份量換算（`lib/nutrition.ts`）
- 份數：`qty ∈ {0.5,1,1.5,2}` 或其他正數；營養素 = 每份 × qty。
- 克數：需要 `servingG`；營養素 = 每份 × grams / servingG，`qty` 存 `grams/servingG`。
- 四捨五入：kcal 整數，營養素 1 位小數，**存檔時才四捨五入**，合計用存檔值加總（App 和 Kyujin 一致）。
- 份量預設：同 `item_id` 最後一筆 Log 的 qty/grams，沒有就 1 份。

### 4.3 體重（一天一筆）
- 主鍵是 `day`。`upsertWeight {day, kg, id, ts}`：該 day 已有未刪除的列就**覆寫** `kg`、`ts`、`updated_at`（這是唯一允許覆寫的寫入，PRD v1.4），否則 append。重送同一 id 視為成功。
- 範圍 30.0–250.0，一位小數；`day` 不能晚於台北今天。
- 復原：新增的那筆 → 軟刪除；覆寫的 → 再寫回原本的 kg（前端記住舊值）。

## 5. API（`gas/Code.gs`）
前端一律 `POST text/plain`，body `{ secret, action, ... }`；回 `{ok:true,...}` 或 `{ok:false,error,message}`。錯誤碼同 sicily-care（`unauthorized`、`bad_json`、`bad_action`、`bad_table`、`bad_record`、`not_found`、`busy`、`server_error`），另加 `forbidden`（Kyujin 想改非自建品項）。

| action | 參數 | 說明 |
|---|---|---|
| `read` | `{since?}` | 回 Config、全部 Items、最近 35 天 Logs、最近 90 天 Weights。4 週熱量仍只用 Logs 的 35 天；體重圖的 3 個月用 Weights 的 90 天。回應含 `weightDays: 90` |
| `append` | `{table:'Logs', record}` | 冪等（重複 id = 成功），驗證四項營養素 |
| `update` | `{table:'Logs', id, patch}` | 改份量；重新驗證四項 |
| `softDelete` / `restore` | `{table, id}` | 軟刪除／復原 |
| `upsertItem` | `{record}` | 自建或 `ov:` 補填；`id` 不能是 `fm:`、`711:` 開頭（回 `forbidden`） |
| `upsertWeight` | `{record}` | §4.3 |
| `setConfig` | `{key, value}` | |
| `history` | `{table, before, limit}` | 往回翻舊的 Logs/Weights，不進 outbox |

- 所有寫入用 `LockService.getScriptLock().tryLock(10000)`，拿不到回 `busy`，前端重試。
- outbox：照 sicily-care `src/api/index.ts`（localStorage、依序、成功才移除、離線每 20 秒重試、連線橫幅規則）。待送的紀錄列標「待上傳」。
- 秘密：共享密鑰由 Brian 在手機輸入，存 localStorage；前端和 repo 不放任何密鑰（`test/security.test.ts` 掃 `src/` 和 `dist/`）。

## 6. 日界線（台北午夜）
- `lib/day.ts`：`taipeiDay(date) = new Date(date.getTime() + 8*3600e3).toISOString().slice(0,10)`；不依賴裝置時區（測試要在 `TZ=America/Los_Angeles` 和 `TZ=UTC` 下都過）。
- `Logs.day` 在前端寫入時算好；後端驗證 `day == taipeiDay(ts)`，不一致回 `bad_record`。補記過去的餐點：使用者改時間，`day` 跟著重算。
- 「今天」在 App 開著跨過午夜時要自動換日（每分鐘檢查，或 `visibilitychange` 時檢查）。
- 週：**週一到週日**（PRD v1.4），`weekStart(day)` 回該週週一。

## 7. 趨勢計算（`lib/trends.ts`，純函式，輸入 Logs/Weights/Config/today）
- 每日合計 `dayTotals[day] = {kcal, protein, fat, carb, count}`（未刪除的 Logs）。
- **不完整的日子**（PRD v1.4）：`day < today` 且（`count ≤ 1` 或 `kcal < 0.5 × target_kcal`）。`count = 0` 也算不完整（沒記）。今天不算。
- 週摘要（選定週，週一–週日，只看 ≤ 今天的日子）：
  - 平均攝取 = 該週**完整日子**的 kcal 平均；沒有完整日子時顯示「—」。
  - 平均赤字 = `tdee − 平均攝取`；負的顯示「平均超過 X kcal/天」；`tdee` 空白時不顯示。
  - 蛋白質達標 = 該週已過完的日子＋今天中 `protein ≥ target_protein` 的天數 / 該週已到的天數（例「5/7 天」；這週還沒完就是「3/4 天」）。不完整的日子也算進分母。
  - 灰字「不含記錄不完整的 N 天」。
- 每日熱量圖：最近 4 個完整的週一到週日（含本週，本週還沒到的日子留空，DESIGN v0.4 §6.11），目標線 = `target_kcal`；今天半透明標「今天」。
- 體重：
  - 7 日移動平均：以 day d 為終點的 7 天內（含 d）有 ≥3 筆體重才算，取平均。
  - 預期變化：起點 = 28 天前那天的 7 日平均（沒有就往後找第一個有值的日子）；之後每天 `expected[d] = expected[d-1] − deficit(d)/7700`，`deficit(d) = tdee − kcal(d)`；不完整的日子用 `tdee − target_kcal`；今天不算。`tdee` 空白就不畫。
  - 文字「4 週少了 0.9 kg」= 今天（或最後一天）的 7 日平均 − 起點；用「少了／多了」不用正負號。
- 沒有資料：完整日子 < 3 天時顯示 DESIGN §6.11 第 5 點文字。
- 測試：每條規則至少一個單元測試，含跨週、跨月、週一起算、今天不算不完整、只 1 筆、49%／50% 邊界、`tdee` 空白、體重同日覆寫。
