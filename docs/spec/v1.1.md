版本：v1.1｜2026-10-10（台北時間）｜作者：Karina
依據：`docs/PRD.md` v1.5 的「快速記一筆」「載入狀態」「常吃店家」（常吃店家取代快速記一筆的「不建品項」）、`docs/design/DESIGN.md` v0.6（含 v0.7 定案）§6.14–6.16 與 mock `stores.png`、`loading.png`、既有規格 `docs/spec/v1.md`、`docs/kyujin-api.md`、`app/` 現有程式。
**v1.md 沒提到要改的地方一律照舊。** UI 細節以 DESIGN.md 為準，本文件只寫資料、API、狀態與測試。

## 1. 範圍
1. 常吃店家：Stores 表、Items 加 `store` 欄、店家膠囊、`StoreSheet`、`StoreItemForm`、搜尋「店名 · 品項」、品項頁「店家」段。
2. 不指定店家（快速記錄）：一次性的 Log，`item_id` 空、自己帶營養素。
3. 載入狀態：IndexedDB 快取快照＋`SyncBadge`「同步中」、無快取時 skeleton、失敗原因＋重試；**永遠不顯示假的預設數字**。
4. 樂觀寫入：所有寫入走現有 outbox，pending／synced／failed 三態；outbox 改存 IndexedDB。
5. Kyujin 權限調整：可建／改店家與店家品項，可新增／修改／刪除 `source=kyujin` 的 Logs。
6. 後端 schema 遷移（既有 Sheet 不重建、冪等）。

不做：店名以外的地點資訊、條碼掃描、App 內等 Kyujin 估算結果、新後端架構（見 `/workspace/studio/docs/architecture/backend-v2-proposal.md`，另案）。

## 2. 資料（`gas/Schema.gs`、`src/types.ts`、`src/data/codec.ts`）
規則照 v1 §4：**不改既有欄位名稱或順序，新欄位只加在最後。**

| 分頁 | 變更 | 欄位 |
|---|---|---|
| `Stores`（新） | 主鍵 `id`（`s:<uuid>`） | `id`, `ts`（建立時間）, `deleted`, `updated_at`, `name`, `last_eaten_at`（ISO，+08:00，可空）, `created_by`（`app`／`kyujin`） |
| `Items` | 最後加 `store` | 店家品項 = `store` 為 Stores.id；一般自建／補填 = 空字串。店家品項一律 `kind=自建`、`src=其他`、id `u:` 開頭 |
| `Logs` | 最後加 `source`、`store` | `source`：`app`（預設，舊列空值視為 `app`）／`quick`（不指定店家）／`kyujin`；`store`：記錄當下的 Stores.id（店家品項才有，用來排序和顯示店名，可空） |

- `Stores.name` 修剪空白後不可空，未刪除的店名不可重複（比對 `norm()` 後相同即重複），重複回 `duplicate_name`（附既有 id，前端顯示「已經有『＜店名＞』」＋「打開這家店」）。
- `last_eaten_at`：後端在 `append Logs` 帶 `store` 時順便更新（同一個 lock 內）；前端樂觀地同步更新本機值。
- 刪除店家＝軟刪除 Stores 列，並把該店未刪除的品項一起軟刪除（同一次寫入、同一個 lock）；`restore` 店家時把**同一次**一起刪掉的品項還原（品項列的 `updated_at` 等於店家刪除時的 `updated_at` 作為判斷）。已記的 Logs 不動。
- 營養素規則不變：店家品項和快速記錄四項營養素都必填、≥0 的有限數字（可為 0）；不存在只有熱量的店家品項或紀錄。
- Logs 照舊存換算後的數字。**改店家品項營養素只影響之後的紀錄**：`upsertItem` 不碰任何 Logs（測試保證）。

### 2.1 快速記錄（不指定店家）
- Log：`item_id=""`、`name` 可空、`src=其他`、`qty=1`、`grams=""`、`source=quick`（App）或 `kyujin`、`store=""`，四項營養素為使用者輸入值。
- 後端：`item_id` 空時必須帶四項營養素（照原驗證）且 `qty=1`；不建 Items 列。
- 前端：`LogRow` 名稱空白時顯示「快速記錄」，第二行「1 筆」；不進搜尋、不進「最近吃過」膠囊、不進品項頁。編輯 Sheet 可改名稱、四項營養素、時間、刪除。
- 畫面不顯示 `source`（PRD：估算紀錄不加標示）。

### 2.2 Schema 遷移（`gas/Setup.gs`）
- 新增 `migrateFoodLog()`（Brian 或 Kazuha 在 Apps Script 編輯器按一次 Run，或 clasp run）：
  - 沒有 `Stores` 分頁就建立並寫表頭；
  - `Items`、`Logs` 表頭缺最後幾欄就**只在最後補**表頭（不移動既有欄、不改資料）；
  - 新欄位設成純文字格式（避免 Sheets 自動轉型，同 fdf6b7c 的提醒時間修正）；
  - 回傳 `{created:[...], addedColumns:{Items:[...],Logs:[...]}}`，重跑第二次全部是空陣列（冪等）。
- `setupFoodLog()` 呼叫同一個 `ensureSheet_`／補欄邏輯，所以新裝與舊表結果一致；不重新產生密鑰。
- 執行期防呆：`handle_` 讀寫前檢查表頭，缺欄時回 `schema_outdated`（訊息「請先執行 migrateFoodLog」），前端顯示錯誤代碼。`header_()` 依表頭名稱找欄，不依位置。
- 部署順序寫進 `app/README.md`：clasp push → 執行 `migrateFoodLog` → 更新正式部署（/exec 網址不變）→ 前端 gh-pages。

## 3. API 變更（`gas/Code.gs`）
| action | 變更 |
|---|---|
| `read` | 多回 `stores`（全部，含已刪除）；`version` 維持 1，前端容忍缺 `stores`（舊後端）時當空陣列 |
| `upsertStore`（新） | `{record}`：新增或改名；冪等（同 id 再送＝更新）；驗證 name、重複名 |
| `softDelete`/`restore` | 支援 `table:'Stores'`（連帶品項，§2） |
| `upsertItem` | 接受 `store`；`store` 非空時必須指向未刪除的 Stores 列，否則 `bad_record` |
| `append`/`update` Logs | 接受 `source`、`store`；`item_id` 空的規則見 §2.1；`update` 可改 `name`、營養素（快速記錄）、qty/grams、ts/day |

衝突：**最後寫的贏**（後端照收到順序覆寫，`updated_at` 由後端填）；**刪除贏過修改**：對 `deleted=TRUE` 的列 `update`／`upsertItem`／`upsertStore` 回 `{ok:true, ignored:"deleted"}`，不改資料、不復活（只有明確的 `restore` 能還原）。前端收到 `ignored` 視為成功並在下次同步時淡出該列。

## 4. Kyujin 權限（`client:"kyujin"`）
| 動作 | 允許條件 |
|---|---|
| `upsertStore` | 任何店家（含 App 建的），新建時 `created_by=kyujin` |
| `upsertItem` | `u:` 自建且 `created_by=kyujin`（照舊）**或**任何 `store` 非空的店家品項（含 App 建的） |
| `append Logs` | `source` 必須是 `kyujin` |
| `update`／`softDelete`／`restore` Logs | 目標列 `source=kyujin`；`update` 不可把 `source` 改掉 |
| 其餘 | `ov:` 補填、官方 id、`setConfig`、非店家的 App 自建品項、刪除店家、App/quick 的 Logs → `forbidden` |

- 「請 Kyujin 估算」是非同步：App 只顯示說明（DESIGN §6.14），不打 API、不等待。Kyujin 建好的店家品項（`created_by=kyujin`）在下次 `read` 出現，品項列標「Kyujin 建檔」（沿用 v1 品項頁標籤）。Kyujin 記的 Log 不加標示。
- 更新 `docs/kyujin-api.md`：新增 `upsertStore`、店家品項、`append/update/softDelete Logs`（`source:"kyujin"`）範例與 forbidden 範例，修正「Kyujin 不可以寫 Logs」的舊說明。密鑰仍寫 `<SECRET>`。

## 5. 前端
### 5.1 常吃店家（DESIGN §6.14）
- 新元件：`StoreChips`（併入 `SearchDock` 膠囊列）、`StoreSheet`、`StoreItemForm`、`StoreForm`（新增／改名）、`StorePicker`（新增店家那一步，最上面「不指定店家」）。
- Dock：店家膠囊最多 3 個（依 `last_eaten_at` 新→舊），品項膠囊在後，整排最多 6 個；高度 < 500px 整排收起。
- `StoreSheet` 品項依該店最後一筆 Log 時間新→舊；點列開 `PortionSheet`（份量預設上次，沒有就 1 份）→「記錄」。
- `StoreItemForm`：「記錄」＝先 `upsertItem` 再 `append Log`（outbox 依序）；「只存品項」只送 `upsertItem`；不指定店家時只有「記錄」、只送 Log。「請 Kyujin 估算」離線時停用並寫「需要網路」。
- 修改營養素（`PortionSheet` 或 `StoreItemForm`）：toast「已更新 ＜品名＞，之後記錄會用新的營養素」，舊 Logs 不重算。
- 品項頁：「我的品項」上面加「店家」段（店名＋「n 個品項 · 上次 M/D」）。
### 5.2 搜尋（`src/data/search.ts`、`catalog.ts`）
- 店家品項加入索引：顯示名「＜店名＞ · ＜品項＞」，索引字串含店名；第二行「店家 · 上次 M/D」。
- 查詢命中店名時，結果最上面多一列「打開 ＜店名＞」。
- 篩選膠囊：全部／收藏／店家／7-11／全家。排序：店家品項與收藏、最近、自建同一區（加權同自建 +10），在 7-11・全家前。
- 快速記錄（`item_id` 空）不進索引。效能測試加 300 個店家品項後 p95 仍 < 30 ms。
### 5.3 載入狀態（DESIGN §6.15）
- `src/data/cache.ts`（新）：IndexedDB（用 `idb-keyval` 或原生，小依賴可接受）存快照 `{savedAt, serverTime, day, config, items, stores, logs, weights}`，每次 `read` 成功後覆寫。
- `useFoodLog` 輸出 `loadState: 'skeleton'|'cached-syncing'|'fresh'|'error-cached'|'error-empty'` 與 `errorKind: 'offline'|'server'|'auth'`＋`errorCode`。
- 快照的 `day` 不是台北今天時：目標、品項、店家、趨勢歷史可用，今天的剩餘卡與今日紀錄用 skeleton。
- **移除所有「沒有資料時用 `defaults.ts` 預設 Config 畫數字」的路徑**：`RemainingSummary`、`MacroBar`、趨勢 KPI、份量 Sheet 的「記錄後還剩」在沒有真資料時畫灰條或「同步後顯示剩餘」。`defaults.ts` 只給後端／測試比對用。
- `SyncBadge`：300ms 內完成不出現；有快取數字時常駐、固定在頂列；快取狀態下剩餘卡數字用 `--muted-foreground`；「已同步」1 秒後淡出。
- 重試：錯誤卡／Badge 的「重試」、回到前景、恢復網路各自動一次。`prefers-reduced-motion` 時不做 shimmer／呼吸／滾動動畫。
### 5.4 樂觀寫入（DESIGN §6.16）
- outbox 從 localStorage 搬到 IndexedDB（第一次啟動把舊 localStorage 佇列搬過去後刪掉；不能掉任何一筆）。依序送、成功才移除照舊。
- 每筆寫入狀態 `pending`→`synced`／`failed`；畫面合計＝已同步＋pending＋未捨棄的 failed。pending 超過 3 秒列上顯示「待上傳」。
- 暫時失敗（網路、`busy`、5xx、逾時）自動重試 2、5、15 秒，之後等回到前景或恢復網路；伺服器拒絕（`bad_record`、`forbidden`、`duplicate_name`、`schema_outdated`）才 `failed`，提供「重試」「捨棄」。
- 復原：pending 中的寫入直接從佇列移除；已送出的送反向寫入。
- 同步合併：`read` 回來後，以伺服器資料為準，再疊上 outbox 中尚未送出的寫入；伺服器上已刪除的列淡出（刪除贏）。
