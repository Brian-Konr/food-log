# food-log v1.1.2：小修（2026-10-11，Brian 回報）

## 1. 首頁蛋白質那行
- 熱量超過時，大字下面那行要寫「還剩 47.8 g 蛋白質」。只有蛋白質真的超過時，才寫「蛋白質超過 X g」。不要只放一個數字。

## 2. 「已更新紀錄 · 復原」toast
- 根因：`App.tsx:741` 每次重畫都傳新的 `onGone`。有紀錄在佇列裡時，App 每秒重畫一次（`App.tsx:210-214`），`UndoToast` 的計時器就每秒重設，結果 toast 要等寫入完成後才會消失。另外，iOS 沒有處理 `pointercancel`／`pointerleave`，toast 可能一直卡著。
- 修法：
  - 計時器只依賴 toast 的 id，固定 3 秒，跟同步狀態無關（同步改 `--toast-ms`、`tokens.css`、DESIGN.md）。
  - 處理 `pointercancel`／`pointerleave`。點一下或往下滑就關掉。

## 3. 「連不到 Google 試算表」橫幅
- 根因：`api/index.ts:252` 只要一次寫入出現 NetworkError，就設 `online=false`；這時佇列裡有紀錄，所以橫幅馬上出現。逾時（55 秒，接近冷啟動的時間）也算在 NetworkError 裡。
- 修法：
  - 寫入失敗時先不顯示橫幅，只把那一列標成「同步中」。等 2／5／15 秒的重試全部用完還是失敗，或連續 2 次 NetworkError，才顯示橫幅。
  - 讀取失敗時，如果有快取資料，不顯示橫幅，用頂列的同步狀態表示。
  - 逾時要當成「狀態未知」，重試時靠 client id 防止重複寫入，不要直接判定為斷線。

## 測試
- toast：佇列裡有紀錄、每秒重畫的情況下，3 秒內要消失。pointercancel 之後也要消失。
- 橫幅：單次寫入失敗、下次重試成功時，不出現橫幅。三次重試都失敗才出現。
- 蛋白質文案：熱量超過、蛋白質沒有超過時，顯示「還剩 … g 蛋白質」。
