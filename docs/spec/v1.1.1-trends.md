# food-log v1.1.1：趨勢頁修正（2026-10-11）

Brian 回報了兩個 bug，以下是修法，已經和他確認過。

## 1. 「記錄不足」判斷
- 現況：`trends.ts` 的 `insufficient = completeDays < 3`，只算今天以前「完整」的日子（每天至少 2 筆、熱量至少達目標的 50%）。所以每天都有記，還是可能顯示「記滿 3 天」。
- 改成：近 4 週內「有任何未刪除紀錄的日子」（包含今天、Kyujin 記的、快速記錄）少於 3 天，才顯示提示。
- 不完整的日子照樣畫在圖上，加上原本的不完整標記；週平均仍然只算完整的日子。本週沒有完整的日子時，週平均顯示「—」，並寫「本週還沒有完整記錄的日子」。
- 提示只放在熱量區塊（週摘要和熱量長條圖的位置），體重卡片不受影響。文字改成「飲食記錄滿 3 天就會出現熱量趨勢（目前 N 天）」。

## 2. 體重圖
- 加一個分段切換：1 週／1 個月／3 個月，預設 1 個月，切換結果記在本機。x 軸是「今天往回推」對應的天數，資料點、7 日平均線、預期線都用同一組 x 軸，並佔滿整個寬度。
- x 軸三個刻度：起點、中點、今天，格式 M/D，最後一個寫「今天」。y 軸三條刻度，取 0.5 kg 的倍數，加淡格線，單位 kg 寫在標題。
- 只有 1 筆體重時，畫一個點加數值，不畫線。區間內沒有資料時，顯示「這段期間沒有體重紀錄」。
- 3 個月需要 90 天的體重資料，但 `read` 目前只給 35 天：需要給 Weights 加上分頁讀取或更長的時間範圍，後端要向下相容（自動 migrate 的規則不變）。
- 更新 DESIGN.md 的 WeightChart 段落（由 Winter 確認）。
