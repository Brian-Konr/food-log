# v1.1.3-sheetfix：Google Sheet 文字欄被自動轉成日期

## 背景（Kyujin 回報，10/12 22:36–22:38 Brian 手動新增 7-11 品項「統一陽光 無加糖超優…」）
1. 存檔失敗：「src 只能是 7-11、全家或其他」，第一筆顯示「沒有存到・重試」。
2. 第二筆有存到，但副標題顯示原始時間字串「2026-07-11T08:00:0…」。
3. Logs 的 `day` 存成「2026-10-12T08:00:00+08:00」，之後更新失敗：「day 必須等於台北日」。

## 根因
- Google Sheets 會把文字 `'7-11'`（src）與 `'YYYY-MM-DD'`（day）自動轉成 Date。
- `normalizeCell_`（app/gas/Code.gs:128）把 Date 一律讀成 ISO 字串 → src 變成 `2026-07-11T…`、day 變成 ISO，驗證失敗。
- Setup 的 `formatColText_`（app/gas/Setup.gs:93）只格式化「現有的資料列」，新列不受保護。
- `appendLog_`（Code.gs:242/294）、`upsertItem_`（Code.gs:477/531）以及其他寫入點用 `appendRow` 寫入，沒有設定格式。
- （待確認）兩筆蛋白質不同（20.6 g vs 28.6 g）：預期是使用者在兩次新增間輸入不同值；plan 階段請確認不是 codec/欄位錯位造成，若是則一併修。

## 修正範圍
### 後端（Apps Script）
1. **寫入**：所有文字欄（Items/Logs/Stores 的 id、day、src、name、ts、updated_at 等字串欄）改為先 `setNumberFormat('@')` 再以 `getRange(row,1,1,n).setValues()` 寫入，取代 `appendRow`。數值欄（kcal/protein/fat/carb/kg 等）維持數字格式、寫入數字。共用 helper（如 `writeRow_(sh, rowIndex, cols, values)`）。
2. **Setup**：`formatColText_` 改為格式化整欄（`getMaxRows()`），套用於 Items/Logs/Stores 的所有文字欄。
3. **防禦性讀取（依欄位）**：`normalizeCell_` 變成知道欄名：
   - `day` 是 Date → `yyyy-MM-dd`（Asia/Taipei）
   - `ts` / `updated_at` 是 Date → ISO
   - `src` 是 Date 且為 7 月 11 日 → `'7-11'`
   - 其他欄位行為不變
4. **遷移**：新增冪等的 `migrateTextColumns_()`，把已被轉成 Date 的 day/src 修回文字並設 `'@'`；接進 `migrateFoodLog()`；以 `Logger.log` 輸出每張表修正的筆數。跑第二次修正數應為 0。
5. `app/gas/FoodLog-AppsScript.gs` 是產生檔：改完 `gas/*.gs` 後跑 `npm run build:gas`，`test/gas-merged.test.ts` 須通過。

### 前端
1. **codec**：讀到 ISO 形式的 src（如 `2026-07-11T…`、7 月 11 日）正規化為 `'7-11'`。
2. **LogRow**：副標題只顯示合法 src（`7-11`／`全家`／`其他`），其他值不顯示，絕不顯示原始時間字串。
3. **retryFailed**：重送前先把可修正的 src 正規化（例如 ISO→`7-11`），再送出。
4. **去重**：重試沿用同一 client id，後端依 id upsert/去重的行為必須保留，不得產生重複列。
