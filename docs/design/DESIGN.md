## 1. 設計原則（food-log）

1. **記錄速度優先**（PRD 最高原則）：首頁 → 記好，常吃品項 **2 下**（膠囊 → 記錄），搜尋品項 **3 下**（搜尋框 → 結果 → 記錄，不算打字）。
2. **一律先看份量再記**（Brian 決定）：任何品項點下去都先開份量 Sheet，預設帶上次記這個品項的份量（第一次記才是「1 份」），再按「記錄」。常吃品項最多 3 下：點品項 → 確認份量 → 記錄（PRD v1.1 驗收第 9 項）。不做點一下就直接記。
3. **只強調一件事**：畫面上只有蛋白質用萊姆色，其他用黑、白、灰。熱量靠大字。
4. **不出現負數**：超過目標時寫「超過 120 kcal」，不顯示「−120」。
5. **安靜的高級感**：沒有插圖、漸層、表情符號；層次靠字級、字重和留白。

## 2. 主題

- **預設深色**（`:root`）。淺色是設定頁的選項：「外觀：深色（預設）／淺色」，存在 `localStorage`，套用到 `<html class="light">`。v0.1 **不跟著系統自動切換**。
- `<meta name="theme-color" content="#0B0B0C">`，切換成淺色時改成 `#F5F5F3`。`apple-mobile-web-app-status-bar-style` 用 `black-translucent`。

- **超過目標**：該營養素的進度條整條換成 `--over` 並填滿 100%，右邊的數字換成「超過 5 g」（`--over`、600 字重）。熱量超過時，大字改成「超過 120」＋「kcal」，下面的小字「今天還剩」改成「今天超過」。熱量超過而蛋白質還沒超過時，蛋白質那一行寫「還剩 47.8 g 蛋白質」（數字仍是 `text-2xl`，一般是萊姆色，快取時 muted）。只有蛋白質真正超過（剩餘 < 0）才寫「蛋白質超過 5.0 g」（整句 `--over`）。不要只放一個數字。

## 4. 字體

```css
--font-family-text:    -apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang TC", "Noto Sans TC", system-ui, sans-serif;
--font-family-display: -apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang TC", "Noto Sans TC", system-ui, sans-serif;
/* Tailwind 用 font-sans／font-display 取用（@theme inline 對應） */
```
所有數字都加 `tabular-nums`（`.tnum`），數字變動時寬度不變。字重只用 400／500／600／700（HIG：避免 Light 以下的細字重）。

| Token | 大小／行高 | 字重 | 用途 |
|---|---|---|---|
| `text-hero` | 52／56，字距 −1.5px | 700 display | 剩餘熱量大字 |
| `text-2xl` | 28／36 | 700 | 剩餘蛋白質（萊姆色） |
| `text-xl` | 20／28 | 700 | 區塊標題「今天的紀錄」、份量 Sheet 品名 |
| `text-lg` | 18／26 | 600–700 | 大按鈕「記錄」、營養素格數字 |
| `text-base`（＝`sm`＝`xs`） | **16／24** | 400–600 | 內文、列、標籤、toast、tab（**最小值**） |

字級用 rem，iOS 的「較大文字」設定才會跟著放大。版面要能容納 1.3 倍字級：列高可以長高，數字欄不截斷。

## 5. 間距、尺寸、圓角

- 4px 基準；畫面左右邊距 16；卡片內距 20；區塊標題上方 20。
- 點擊區 ≥44（`--touch-min`）；搜尋框、份量按鈕 48（`--control-h`）；常吃膠囊、篩選膠囊 44（`--chip-h`）；紀錄列和結果列 ≥60（`--row-min-h`）；「記錄」大按鈕 56。
- 圓角：卡片 22（`--radius`）；搜尋框和膠囊 24／全圓（`--radius-field`）；份量按鈕、營養素格 12；Sheet 上緣 16（`--radius-sheet`）；toast 14。
- 陰影：深色模式幾乎不用陰影，層次靠 `--border`；只有 toast 和 Sheet 有陰影。
- **底部固定區**：tab bar 49＋`--safe-bottom`；上面的 dock（常吃膠囊＋搜尋框）是 `--dock-h` 116。捲動內容的底部 padding ＝ dock＋tab bar＋16，**最後一列不會被蓋住**。

- **矮畫面**（視窗高度 < 500px，例如橫向）：今天頁底部的常吃膠囊收起，只留搜尋欄，讓摘要卡不被擋住；常吃品項改從搜尋 Sheet 的「收藏・最近吃過」選。

## 6. 元件

### 6.1 剩餘額度卡 `RemainingSummary`（首頁第 1 塊）
- `card`，圓角 22、1px `--border`、內距 20。
- 「今天還剩」（16/600 muted）→ 熱量大字 `text-hero`＋「kcal」（muted）→ 蛋白質 `text-2xl` 萊姆色＋「g 蛋白質」（muted）→ 四條營養素進度條。熱量超過而蛋白質還沒超過時，蛋白質那一行寫「還剩 47.8 g 蛋白質」（數字仍是 `text-2xl`，一般是萊姆色，快取時 muted）。只有蛋白質真正超過（剩餘 < 0）才寫「蛋白質超過 5.0 g」（整句 `--over`）。不要只放一個數字。可見字用 `g`，讀屏用「公克」，跟現有 `aria-label` 一致。
- 數字＝目標減掉今天的合計（台北時間換日）；紀錄一定有四項營養素，不會有只有熱量的紀錄。
- 點這張卡不會做任何事（v0.1 不做詳細頁）。

### 6.2 營養素進度條 `MacroBar`
- 順序：熱量、蛋白質、碳水、脂肪。每條是標籤（左）＋「已吃 / 目標 單位」（右，muted、tnum）＋6px 軌道。
- 填色：熱量 `--macro-kcal`、蛋白質 `--macro-protein`、碳水 `--macro-carb`、脂肪 `--macro-fat`。
- **超過目標**：整條填滿 `--over`，右邊文字換成「超過 5 g」。不顯示負數，也不畫超出軌道的部分。
- 讀屏：`role="progressbar"`、`aria-valuenow`、`aria-valuemax`、`aria-valuetext="脂肪 70 / 65 公克，超過 5 公克"`。

### 6.3 紀錄列 `LogRow`（首頁第 2 塊）
- 放在 `card` 裡，列和列之間用 1px `--border` 分隔，列高 ≥60。
- 左：時間（muted、tnum，寬 46）。中：品名（600，一行，太長就截斷）＋「來源 · 份量 · 標籤」（muted）。右：kcal（600）＋「蛋白 x g」或「—」。來源只顯示 `7-11`、`全家`、`其他`。其他值（試算表把 `7-11` 轉成的時間字串）不顯示，第二行只留份量和既有的「待上傳」「同步中」。快速記錄仍是「1 筆」。店家列仍寫店名（§6.14）。
- 點列開「編輯紀錄」Sheet（份量、刪除）。刪除不跳確認，跳 toast「已刪除 鮪魚飯糰・復原」。往左滑刪除只是捷徑，Sheet 裡一定有「刪除」按鈕。

### 6.4 底部搜尋區 `SearchDock`
- 固定在 tab bar 上方，背景由 `--background` 往上漸淡成透明。
- 上排：常吃膠囊，橫向捲動，3–6 個。順序是收藏優先，再來是最近吃過，每個顯示「品名＋kcal」。點了會開**份量 Sheet**（§6.7）。
- 下排：搜尋框，高 48、圓角 24、`--secondary` 底，提示文字「搜尋店家、7-11、全家、我的品項」（v0.6）。點了會開**搜尋 Sheet**（§6.5），並在點擊時對焦，叫出鍵盤。

**新增品項 `StoreItemForm`**（同一個 Sheet 換頁，左上「‹ 返回」44px）
- 欄位：品名（必填，16px，`enterkeyhint="next"`）→ 四個數字欄：熱量、蛋白質、碳水、脂肪（每份，`inputmode=decimal`，44 高，標籤在欄位上方）。四欄都要填（可以填 0）才能存，**跟「要補營養素」同一條規則：不會有只有熱量的店家品項**。
- 欄位上方一個次要按鈕「請 Kyujin 估算」（48 高、`--secondary` 底）。按了不在 App 裡等結果：Sheet 顯示說明「傳照片或品名給 Kyujin，估好後會出現在這家店」，按鈕「好」關閉 Sheet。這個品項由 Kyujin 建，App 重新整理（或下次同步）後出現在店家清單，標「Kyujin 建檔」。（Karina 2026-10-10 定案：App 不等結果，下次同步出現並標「Kyujin 建檔」）
- 主按鈕「記錄」（56）：存品項＋直接開份量頁記一筆（新品項一樣先看份量，預設 1 份）。另有文字按鈕「只存品項」（44）。
- **不指定店家（快速記錄）**（v0.7，Karina 定案）：「新增店家」那一步的店家清單最上面多一列「不指定店家」（≥60，`--primary` 文字）。點了直接到品項表單，**品名可以空白**，四個營養素照樣要填（沿用「不會有只有熱量的紀錄」規則，和 PRD「手動輸入熱量和三大營養素」一致，不衝突）。表單只有「記錄」，沒有「只存品項」。這種紀錄**不建品項、不進店家、不出現在搜尋和品項頁**，只記這一筆；`LogRow` 品名空白時顯示「快速記錄」，第二行寫「1 筆」。資料層 `source=quick`。
- **搜尋 Sheet 也有「不指定店家」**（v0.8）：搜尋 Sheet 沒打字時，最上面放一列「不指定店家」：一般次要列，`--muted-foreground` 文字＋`PenLine` icon，高度 ≥44，不做成膠囊，也不搶常吃店家的視覺焦點。點了直接到快速記錄表單。直向 3 下：不指定店家 → 填營養素 → 記錄。
- **新增店家**：只有一個店名欄＋「建立」，建好直接進這家店的 `StoreSheet`（空清單＋「＋ 新增品項」）。店名重複時提示「已經有『＜店名＞』」並提供「打開這家店」。

**點擊次數**（PRD 驗收：≤3 下）
- 已有的店家品項：**店家膠囊 → 品項 → 記錄＝3 下**（份量預設 1 份，不用動）。
- 從搜尋：點搜尋框 → 打字（不算）→ 點結果 → 記錄＝3 下。
- 矮畫面：點搜尋框 → 常吃店家 → 品項 → 記錄＝4 下。**3 下的驗收只看直向**（Karina 定案），橫向 4 下可以接受。

**搜尋結果**
- 店家品項的結果列，第一行寫「＜店名＞ · ＜品項＞」，例如「阿財牛肉麵 · 牛肉麵」（店名 muted 500、品項 600；太長時先截店名）；第二行「店家 · 上次 10/9」。讀屏「阿財牛肉麵，牛肉麵，店家品項，650 大卡，蛋白質 38 公克」。
- 店名本身也比對：打「阿財」會出這家店的全部品項，最上面多一列「打開 阿財牛肉麵」（`Store` 圖示，點了開 `StoreSheet`）。
- 排序：店家品項和收藏、最近吃過、自建放在同一區（第一區），排在 7-11・全家前面。

**修改**
- 份量 Sheet 和 `StoreItemForm` 都可以改營養素；改了以後**之後的紀錄用新值，已記過的不變**。存的時候 toast「已更新 ＜品名＞，之後記錄會用新的營養素」。
- 品項頁（§6.13）在「我的品項」上面加一段「店家」：每列是店名＋「n 個品項 · 上次 10/9」，點了開 `StoreSheet`。

**紀錄列**：店家品項的 `LogRow` 第二行來源寫店名，例如「阿財牛肉麵 · 1 份」。Kyujin 記的那筆和一般紀錄一樣，不加標示（PRD v1.5）。

### 6.15 載入狀態 `LoadState`（v0.6，PRD v1.5「載入狀態」）

**規則：畫面上永遠不出現不是真資料的數字。** 沒有資料就畫灰條，不畫 2,000 kcal、0 筆。

| 狀態 | 什麼時候 | 畫面 |
|---|---|---|
| `cached-syncing` | 打開 App，本機有上次的快取，後端還沒回來 | 照快取畫出全部內容（數字、紀錄、圖）；首頁頂列日期旁邊出現 `SyncBadge`「同步中」 |
| `skeleton` | 沒有快取（第一次打開、清過資料） | 骨架：卡片框照常畫，數字位置是灰條 |
| `fresh` | 後端回來了 | 換成真資料，`SyncBadge` 淡出 |
| `error-cached` | 有快取、載入失敗 | 留著快取，`SyncBadge` 換成「沒有同步 · 重試」 |
| `error-empty` | 沒快取、載入失敗 | 骨架換成錯誤卡：原因＋「重試」 |

**快取的日期**：快取是昨天（台北時間換日了）的話，今天的剩餘額度**不能**用昨天的數字。只保留目標（設定）、品項庫、店家、趨勢的歷史，今天的卡和今日紀錄用骨架，等後端回來。

**`SyncBadge`**（同步標示）
- 位置：首頁頂列日期右邊、體重圖示左邊；其他分頁在大標題右邊。高 32、圓角全圓、`--secondary` 底＋1px `--input` 外框，文字 16/600 `--foreground`（不用 muted），圓點用 `--primary`。點擊區 44（透明延伸）。
- **一定要看得到**（v0.7，Karina：快取數字可以先顯示，前提是標示清楚）：只要畫面上有快取數字，`SyncBadge` 就一直在，不能被 Sheet 以外的東西蓋住、不能捲出畫面（跟著頂列固定）；橫向和放大字級時也不能截掉。快取狀態下，剩餘額度卡的數字用 `--muted-foreground`，同步完才換回正常顏色（顏色交叉淡化 200ms），雙重提示「這是上次的數字」。讀屏在卡片上加「上次的資料，同步中」。
- 「同步中」前面一個 12px 的小圓點，1.2 秒呼吸（opacity 0.4↔1）；減少動態效果時不動。
- 同步好：顯示「已同步」1 秒後淡出 250ms（不常駐）。
- `role="status"`、`aria-live="polite"`；只在狀態改變時讀，不重複讀「同步中」。
- 如果 300ms 內就同步好，`SyncBadge` 不出現，避免閃一下（這時快取數字也只停留不到 300ms）。
- 同步後數字一定用平順換法（見下面「資料回來的換法」），不能直接跳。

**Skeleton**
- 灰條用 `--muted` 底、圓角 6，高度＝那一行字的高度（hero 數字 56、一般字 16），寬度用固定比例（不隨機），排版和真資料一樣，換掉時不跳版。
- 剩餘額度卡：「今天還剩」標籤照常顯示（是固定文字，不是資料），熱量、蛋白質是灰條；四條進度條只畫軌道，不畫填色，右邊數字是灰條。
- 今日紀錄：3 列骨架列（時間、品名、kcal 都是灰條），不寫「今天還沒有紀錄」（那是真資料才能說的話）。
- 趨勢：三格摘要是灰條；圖區是一塊 `--muted` 方塊，不畫假長條。
- 骨架上面加一道很淡的光（shimmer）1.5 秒循環；減少動態效果時不動。`aria-busy="true"`，讀屏讀「載入中」一次。
- 骨架狀態時搜尋 dock 還是可以用（搜尋是本機目錄）；份量 Sheet 的「記錄後還剩」預覽在沒有今天的資料時改寫「同步後顯示剩餘」。

**資料回來的換法**
- 骨架 → 真資料：交叉淡化 200ms（`opacity`），版面不動。
- 快取 → 新資料：數字有變就照 §7 的數字滾動 300ms、進度條 400ms；新出現的紀錄列淡入，被刪掉的淡出。不整頁重畫、不跳回頂端。
- 減少動態效果時直接換。

**載入失敗**
- 原因要講白話，分三種：「沒有網路連線」「伺服器沒有回應，可能是暫時的問題」「登入過期，請重新打開」（後端錯誤代碼放在第二行 muted 小字，方便回報，例如「錯誤代碼 GAS-503」）。
- `error-empty`：剩餘額度卡的位置換成錯誤卡（同 card 樣式），標題「讀不到今天的資料」、原因一行、「重試」主按鈕 48 高。今日紀錄區不顯示。
- `error-cached`：內容照快取，`SyncBadge` 變成「沒有同步 · 重試」（`--destructive` 文字＋圓點，點了重試）。不跳 modal、不擋操作。
- 重試時按鈕變「重試中…」並停用；自動重試：回到前景、恢復網路時各自動重試一次。

### 6.16 樂觀寫入 `WriteState`（v0.6）

所有寫入（記錄、刪除、改份量、補營養素、記體重、收藏、店家／品項新增修改、設定）都是**一按就改畫面，背景再同步**。每一筆寫入有三個狀態：

| 狀態 | 畫面 |
|---|---|
| `pending`（還在送） | 跟已同步長得一樣；剩餘額度、進度條、趨勢立刻算進去。不轉圈、不顯示「儲存中」。超過 3 秒還沒好，該列第二行尾端出現「待上傳」（muted 文字，沿用 §9 標籤） |
| `synced` | 「待上傳」拿掉，不另外慶祝 |
| `failed`（重試後仍失敗） | 該列第二行換成「沒有存到 · 重試」（`--destructive` 文字＋`AlertCircle` 16px），整列可以點開，Sheet 最上面一行原因＋「重試」「捨棄」兩顆 48 高按鈕；同時跳 toast「＜品名＞沒有存到・重試」（3 秒，跟一般 toast 一樣） |

**各元件**
- **`LogRow`**：新增的列立刻出現在清單（照時間排）；刪除的列立刻淡出。失敗的新增留在清單，標「沒有存到 · 重試」，**還是算進剩餘額度**（使用者以為記了，數字要一致），並在剩餘額度卡下面多一行 muted「有 1 筆沒有存到」。選「捨棄」才扣回。失敗的刪除：列淡入回來，toast「刪除失敗，已還原 ＜品名＞・重試」。
- **`RemainingSummary`／`MacroBar`**：一律用「已同步＋pending＋failed 未捨棄」的合計，不分開畫。
- **`WeightSheet`**：按記錄就關閉，趨勢頁 7 日平均立刻更新；失敗時趨勢頁體重卡「＋ 記體重」旁邊顯示「72.4 kg 沒有存到 · 重試」。
- **設定（每日目標、每日消耗）**：存了立刻生效；失敗時欄位下面一行「沒有存到 · 重試」，值保留在欄位裡，不跳回舊值。
- **收藏／取消收藏、`StoreItemForm`、新增店家**：立刻反映（膠囊、清單、搜尋）；失敗時 toast 加「重試」，並把畫面還原成伺服器的狀態（收藏星星跳回）。
- **補營養素**：營養素存回品項跟那筆紀錄是同一次寫入；失敗時兩個一起當 `failed`，重試一起送。

**和「復原」的關係**
- 復原 toast（§6.8）是 3 秒。按「復原」＝送一筆反向寫入（新增→刪除，刪除→還原，更新→改回舊值），畫面立刻還原。
- 如果原本那筆還在 `pending`：直接把它從佇列拿掉，不送出，也就不用反向寫入。
- 如果是 `failed` 的紀錄：「捨棄」等於復原，不跳第二個 toast。
- 同一時間只有一個 toast：新的取代舊的時，舊的那筆照原本的寫入繼續送（不會因為 toast 消失而取消）。

**離線**
- 寫入排進本機佇列（依序送，存在 IndexedDB，關掉 App 也不會掉），列上標「待上傳」，不算失敗。
- 頂列 `SyncBadge` 顯示「離線 · 2 筆待上傳」（muted，不是紅色）。恢復連線自動送出，送完「已同步」淡出。
- 離線時搜尋、記錄、記體重、復原都可以用；只有「請 Kyujin 估算」要網路，按鈕停用並寫「需要網路」。
- 送出時伺服器拒絕（例如未來日期的體重、資料格式錯）才算 `failed`；暫時連不上一律自動重試（間隔 2、5、15 秒，之後等下次回到前景或恢復網路）。

**和 Kyujin 的寫入**（v0.7，Karina 定案）：Kyujin 新增或修改的紀錄、店家、品項在下次同步時合併。衝突規則：**最後寫的贏；刪除贏過修改**（任一邊刪了，這筆就刪掉，另一邊的修改丟掉）；不問 Brian、不跳提示。被別人刪掉的列在同步時淡出。

## 7. 互動與動態

| 動作 | 動態 | 減少動態效果時 |
|---|---|---|
| Sheet 開啟／關閉 | 由下往上，`--dur-sheet` 350ms、`--ease-spring`；遮罩淡入 250ms | 只淡入淡出 150ms |
| 進度條數值改變 | 寬度變化 `--dur-bar` 400ms、`--ease-spring`；超過目標時顏色在 250ms 內換成 `--over` | 直接換 |
| 剩餘數字改變 | 數字滾動 300ms（tnum 寬度不變） | 直接換 |

| 記錄成功 | 「記錄」按鈕先打勾 200ms，接著 Sheet 關閉、toast 由下滑入 | toast 直接出現 |
| Toast 消失 | 往下淡出 250ms | 淡出 |
| 趨勢圖第一次出現 | 長條由下往上長出、線條由左往右畫出，400ms | 直接顯示 |
| 載入：骨架 → 真資料 | 交叉淡化 200ms；骨架 shimmer 1.5s 循環 | 直接換，不 shimmer |

| 體重「−」「＋」 | 數字直接換（tnum），按下縮到 0.97；按住 0.5 秒後每 100ms 連續加減 | 一樣（不是動畫） |

- **震動回饋**：iOS Safari 不支援 `navigator.vibrate`，改用上表的視覺回饋，不寫震動程式。
- 往下滑關閉 Sheet、往左滑刪除紀錄都只是捷徑，一定有看得到的按鈕可以做同一件事（取消、刪除）。
- 所有動畫用 CSS `transition`／WAAPI，只動 `transform` 和 `opacity`（進度條寬度用 `transform: scaleX`），避免捲動卡頓。

## 8. 可近用性

- 照 Studio §9 checklist；另外：
- 深色、淺色兩套都要過對比表（§3.3），改色就重跑 `build.py`。
- 狀態一定有文字：超過目標、要補營養素、Kyujin 建檔、待上傳；碳水和脂肪不能只靠灰色深淺區分。
- 點擊區 ≥44；常吃膠囊之間間距 8。
- 焦點：Sheet 開啟時焦點移到 Sheet 內（搜尋 Sheet 移到輸入框，份量 Sheet 移到「記錄」按鈕），關閉後焦點回到觸發的元件。焦點外框是 2px `--ring`。
- 讀屏：剩餘額度卡讀成「今天還剩 900 大卡，蛋白質 75 公克」；結果列讀成「原味雞胸肉，7-11，136 大卡，蛋白質 28.1 公克，收藏」。
- 「較大文字」放大到 1.3 倍時，版面不能截掉數字。

### 8.1 圖表可近用性（v0.3）
- 每張圖都是 `<svg role="img">`，加 `<title>`，`aria-describedby` 指到圖下面的**文字摘要**（看得到，16px muted），例如：「近 4 週平均 2,040 kcal，11 天超過目標，3 天記錄不完整（9/16、9/24、10/2）。」「體重 7 日平均 72.9 kg，4 週少了 0.9 kg；依赤字預期少 1.1 kg。」
- VoiceOver 可以逐日讀：圖下面放一個「看每日數字」的展開按鈕（44 高），展開後是 28 列的表格（日期、熱量、蛋白質、體重、是否完整），讀屏和放大字級都能用。圖本身不做逐點的焦點，避免讀屏要滑 28 次。
- 數字全部 tnum；圖上的文字（日期、圖例）≥16px。
- 不完整、目標線、預期線都不只靠顏色（圖樣、虛實線、「!」和圖例文字）。

## 9. 文案

- 用「記錄」（動詞、按鈕）；「紀錄」（名詞、清單）。
- 單位：kcal、g，數字和單位之間空一格（「900 kcal」「28.1 g」）；份量用「1 份」「½ 份」「180 g」。
- 剩餘：「今天還剩」；超過：「今天超過」「超過 120 kcal」。**不出現負數**，也不用「爆了」「警告」這種詞。
- Toast：「已記錄 ＜品名＞ ＜份量＞」「已刪除 ＜品名＞」，按鈕「復原」。
- 搜尋提示「搜尋 7-11、全家、我的品項」；找不到「找不到『＜關鍵字＞』」；按鈕「手動新增品項」。
- 標籤：「要補營養素」「Kyujin 建檔」「★ 收藏」「待上傳」。
