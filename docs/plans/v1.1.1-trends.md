## 0. 已定案、不要再猜

### 0.1 「記錄不足」只看「有沒有記」，不看「完整不完整」

近 4 週 = 熱量圖那 28 格，不是從今天往回滾 28 天。起點是 `addDays(weekStart(today), -21)`，終點是該日起第 28 天（含未來的週日）。`kcalBarSlots` 已經產出這 28 格。

「有紀錄的一天」= 這一格 `slot !== 'future'` 且 `count > 0`。

- `count` 沿用 `sumLogs`：`deleted === true` 的列不算。一整天只有軟刪除紀錄 → 這天不算。
- 今天算。Kyujin（`source: 'kyujin'`）算。快速記錄（`source: 'quick'`，品名可空）算。不要依 `source` 過濾。
- 同一天多筆只算 1 天。
- 28 格起點之前的紀錄不算，即使它離今天不到 28 天。
- 未來格不算。

```ts
const loggedDays = slots.filter((s) => s.slot !== 'future' && s.count > 0).length
const insufficient = loggedDays < 3
```

`completeDays` 欄位留著，演算法不要改，但畫面門檻改用 `loggedDays`。不要再寫 `insufficient: completeDays < 3`。

提示**只取代熱量區塊**（三格摘要＋「不含記錄不完整…」＋熱量圖＋「看每日數字」）。體重卡在這個分支外面，維持現在 `TrendsScreen` 的結構，有未刪除體重就照畫。

文案一字不改（數字前後留半形空格，全形括號）：

```text
飲食記錄滿 3 天就會出現熱量趨勢（目前 ${loggedDays} 天）
```

`loggedDays === 2` 時畫面上要有子字串 `目前 2 天`。不要再用舊句「還沒有足夠的紀錄，記滿 3 天就會出現趨勢。」

`insufficient === true` 時不要同時顯示「本週還沒有完整記錄的日子」。

`insufficient === false` 時：

- 不完整的日子仍走現有 `KcalBarChart`（斜線、外框、「!」、圖例）。不要改不完整的定義。`isIncomplete` 維持：今天永遠不是不完整；今天以前 `count <= 1` 或熱量 &lt; 目標 50% 才是不完整。
- 週平均仍只算完整日（`weekSummary` 不要改）。`avgKcal == null` 時「平均攝取」維持「—」，並在摘要下方加一行 muted：`本週還沒有完整記錄的日子`。看的是畫面上選中的那一週（`mon`），文案仍用這八個字，翻到上週也用這句，不要改成「上週」。
- 星期一且這一週只有今天：今天不進完整日平均，`avgKcal` 是 null。若近 4 週已有 ≥3 個有紀錄的日子，不顯示「記錄不足」，要顯示「—」和「本週還沒有完整記錄的日子」。不要為星期一加特例。
- 既有的「不含記錄不完整的 N 天」「先到設定填每日消耗，就能看到赤字」「平均超過」都留著。順序：三格 → 平均超過（若有）→ 不含記錄不完整（若 `incompleteDays > 0`）→ 本週還沒有完整記錄的日子（若 `avgKcal == null`）→ 每日消耗那句（若 tdee 空）→ 熱量圖。

`Trends.gs` 的 `weekSummary_` / `isIncomplete_` 不要改。Kyujin 的 `trends` action 仍只回週摘要。

### 0.2 體重區間：7／30／90 天，含今天

| 鍵 | 畫面 | 天數（含今天） | 起點 |
|---|---|---|---|
| `1W` | `1 週` | 7 | `addDays(today, -6)` |
| `1M` | `1 個月` | 30 | `addDays(today, -29)` |
| `3M` | `3 個月` | 90 | `addDays(today, -89)` |

預設 `1M`。不要做成「今天減 7／30／90」那種 8／31／91 天。

x 軸永遠是這 N 天，佔滿繪圖區寬度。點在哪一天就畫在哪一天，不要把點集中後再拉滿。7 日平均線、預期線用同一個 x。

中點日：`days[Math.floor((N - 1) / 2)]`（N 為奇數時正中間；N=30 取 index 14）。以今天 `2026-10-11` 為例：

- 1 週：`10/5`、`10/8`、`今天`
- 1 個月：`9/12`、`9/26`、`今天`
- 3 個月：`7/14`、`8/27`、`今天`

日期用現成的 `formatMd`（不補零）。最後一格的文字是 `今天`，不要再印今天的日期。

### 0.3 90 天體重：拉長 `read`，不要改表

`read` 現在 Logs 和 Weights 都是 `day >= 今天 - 34`（35 天）。改成：

- Logs 維持 `day >= addDays(today, -34)`（35 天，含已刪除，`since` 行為不變）。
- Weights 改成 `day >= addDays(today, -89)`（90 天，含已刪除，`since` 行為不變）。
- 回應多一個欄位 `weightDays: 90`。不要升 `version`。不要新 action。不要改 `history`（仍是預設 35、上限 90）。不要改 `SCHEMA`、欄位順序、`schema_version`、`DEFAULT_CONFIG`。自動 migrate 規則不動。

前端不要為了 3 個月再打 `history`。一次 `read` 就夠。

預期線仍用記憶體裡的 Logs。35 天以前的日子沒有 log 列，`isIncomplete` 會把它當不完整，步伐是 `(tdee - targetKcal) / 7700`。這是定案。不要為了預期線把 Logs 也放寬到 90 天。

7 日平均的 6 天暖身：90 天窗口的第一天（今天−89）看不到今天−95…今天−90 的體重，平均線可以晚幾天才出現。不要把 Weights 改成 96 天。

舊後端沒有 `weightDays`、Weights 仍只有約 35 天。前端不要當錯誤。1 週和 1 個月照畫。3 個月在「這次回應還沒被證明是 90 天」且仍在同步時，圖的位置畫骨架，不要先把 35 天的線畫上去再拉長（DESIGN §6.11）。同步完成後（`fresh` 或 `error-cached`）用手上有的點畫在 90 天的軸上，左邊留白可以。

```ts
export type WeightRange = '1W' | '1M' | '3M'
export const WEIGHT_RANGE_DAYS: Record<WeightRange, number> = { '1W': 7, '1M': 30, '3M': 90 }

export function parseWeightRange(raw: string | null | undefined): WeightRange {
  return raw === '1W' || raw === '1M' || raw === '3M' ? raw : '1M'
}

/** 三條 y 刻度，全部是 0.5 kg 的倍數，包住資料且上下至少各 0.5 kg。 */
export function weightYTicks(values: number[]): { min: number; max: number; ticks: [number, number, number] } {
  const toU = (kg: number) => Math.round(kg * 100) // 0.01 kg
  const dMin = Math.min(...values.map(toU))
  const dMax = Math.max(...values.map(toU))
  const lo = dMin - 50
  const hi = dMax + 50
  let step = 50 // 0.5 kg
  while (step * 2 < hi - lo) step += 50
  const mid0 = Math.round(((dMin + dMax) / 2) / 50) * 50
  for (let guard = 0; guard < 12; guard++) {
    const bottom = mid0 - step
    const top = mid0 + step
    if (bottom <= lo && top >= hi) {
      const ticks = [bottom, mid0, top].map((u) => u / 100) as [number, number, number]
      return { min: ticks[0], max: ticks[2], ticks }
    }
    step += 50
  }
  const ticks = [mid0 - step, mid0, mid0 + step].map((u) => u / 100) as [number, number, number]
  return { min: ticks[0], max: ticks[2], ticks }
}
```

## 4. 邊界（實作時照著做，不要另選）

- 軟刪除的飲食日不算進 N。軟刪除的體重不畫點；若區間內只剩軟刪除，顯示「這段期間沒有體重紀錄」。
