## 0. 三個已定案、不要再猜

### 0.1 店家品項的「記錄」按鈕

DESIGN §6.14：新品項要先看份量。規格 §5.1：outbox 先 `upsertItem` 再 `append`。兩者一起做，不要合成一顆按鈕直接記 1 份：

1. `StoreItemForm` 的「記錄」只送 `upsertItem`，送出後立刻打開既有的 `PortionSheet`（沒吃過預設 1 份；吃過用 `lastPortion`）。
2. `PortionSheet` 的「記錄」才 `append` Log。outbox 順序自然是先品項、再紀錄。
3. 「只存品項」只送 `upsertItem`，不開份量 Sheet，回到該店的 `StoreSheet`。
4. 已存在的店家品項不走這個表單。路徑是：店家膠囊 → 品項列 → 份量 Sheet「記錄」＝ 3 下。

### 0.2 不指定店家（快速記錄）只有 3 下

PRD／規格要求從打開 App 到記好 ≤ 3 下，打字不算。DESIGN 把「不指定店家」放在「新增店家」那一步；若唯一入口是「搜尋框 → ＋ 新增店家 → 不指定店家 → 記錄」會變成 4 下。

做法（兩處同一列、同一個表單）：

- 搜尋 Sheet **還沒打字**時，「常吃店家」標題下面第一列就是「不指定店家」（整列 ≥ 60、`--primary` 字）。這是 3 下路徑：搜尋框 → 不指定店家 →（打營養素）記錄。
- `StorePicker` 清單最上面再放一列相同的「不指定店家」，給從「＋ 新增店家」進來的人。
- 快速記錄表單只有「記錄」。按下去只 `append` 一筆 Log，**不**建 Items、**不**開份量 Sheet、`qty` 固定 1。

### 0.3 搜尋分組的名字衝突

`SearchHit.group` 現有的 `'store'` 代表「7-11・全家」那一區，不是餐廳。餐廳品項放進既有的 `'fav-recent'`（和收藏、最近、自建同一區，標題維持「收藏・最近吃過」）。不要把餐廳品項畫到「7-11・全家」下面。不要為了改名去重寫舊測試的分組字串；維持 `'fav-recent' | 'store'` 這個 union。

## 4. API（`app/gas/Code.gs` 與 `app/src/api/mock.ts` 同時改）

`mock.ts` 的每個新分支要和 GAS 同一套規則、同一個 `error` 字串。本機試用是 e2e 的後端。`createMockAdapter` 已收下 `latencyMs` 但沒有使用；這次要真的 `await` 延遲再 `handle`。`call()` 若 `navigator.onLine === false`（或 `setOffline(true)`）丟 `NetworkError`。

### 4.1 `read`

回傳多一個 `stores`：全部列，含已刪除。`version` 仍是 `1`。`items`／`logs`／`weights` 的篩選天數不變。

### 4.2 `upsertStore`（新）

請求：`{ action:'upsertStore', record:{ id, name, ts?, created_by? } }`。

驗證順序：

1. 沒有 `id`，或 `id` 不以 `s:` 開頭 → `bad_record`。
2. 同 id 已存在且 `deleted` → `{ ok:true, ignored:'deleted' }`，不改儲存格、不復活。
3. `name` trim 後是空的 → `bad_record`「店名不能空白」。
4. 其他未刪除店家，`normName_(name)` 相同且 id 不同 →  
   `{ ok:false, error:'duplicate_name', message:'已經有「＜既有顯示名＞」', existingId, existingName }`。  
   比對用規格講的 `norm()`。把 `src/data/search.ts` 的 `norm` 原樣抄成 GAS `normName_`（NFKC、toLowerCase、去掉同一組標點與空白）。自己改名成同一個 norm 不算重複。已刪除店家的名字可以再用。
5. 新列：App 的 `created_by` 寫 `app`。Kyujin 新建必須 `created_by==='kyujin'`，否則 `forbidden`。更新時保留原本的 `created_by`，不要被請求蓋掉。
6. 同 id 再送＝改名，不插第二列。`updated_at` 由後端寫。

`norm` 的對照測試（GAS 與 `search.ts` 各寫一條，向量相同）：

- `norm(' 阿財牛肉麵 ') === norm('阿財・牛肉麵') === norm('阿財牛肉麵')`
- `norm('ABC麵') === norm('abc麵')`

### 4.3 `softDelete`／`restore` 支援 `Stores`

`softDelete`：

- Kyujin：`forbidden`（在查到列之前也是 `forbidden`，讓 `gas-kyujin.test.ts` 對不存在的 id 仍是 `forbidden`）。
- 店家列設 `deleted=TRUE`，`updated_at` 設成這次的 `now`。
- 同一個 lock、同一個 `now`：所有 `store===這家 id` 且尚未刪除的 Items 也設 `deleted=TRUE`、`updated_at=now`。
- Logs 不要動。

`restore`：

- Kyujin：`forbidden`。
- 店家 `deleted=FALSE`，寫新的 `updated_at`。
- 把 `store===這家 id`、目前已刪除、且 `updated_at` **等於店家刪除當下那個舊的 `updated_at`** 的品項設回 `deleted=FALSE`。更早以前單獨刪掉的品項（`updated_at` 不同）留在刪除。Logs 不動。

實作時先把店家列上「刪除當下的 `updated_at`」讀進區域變數，再改店家列，再用那個舊值去比品項。

### 4.4 `upsertItem` 的 `store`

- 既有 `u:`／`ov:`／官方 id 規則保留。
- `store` 空或沒送：維持現在的行為。Kyujin 仍只能寫自己 `created_by===kyujin` 的 `u:`。
- `store` 非空：必須是未刪除的 `Stores.id`，否則 `bad_record`「找不到這家店」。且 `kind==='自建'`、`src==='其他'`、id 以 `u:` 開頭。否則 `bad_record`。
- Kyujin 對 `store` 非空的品項：可以新增，也可以改 App 建的。這條放寬只在 `store` 非空時生效。`ov:`、`fm:`、`711:`、沒有店家的 App `u:` 仍是 `forbidden`。
- 目標列已刪除：`{ ok:true, ignored:'deleted' }`，不改資料。
- 改 `kcal` 等欄位之後，用測試讀回 Logs，斷言每一格都沒變。

### 4.5 `append`／`update` Logs

`appendLog_` 現在要求 `item_id` 和 `name` 都有值。改成：

- 一般紀錄（`item_id` 非空）：維持現在的必填、`name` 不可空、`qty>0`、營養素、`src`、`day===台北日`、不可未來、同 id 重複視為成功。
- 快速紀錄（`item_id===''`）：必須 `nutritionOk`、`qty===1`、`grams` 空、`src==='其他'`、`store===''`、`name` 允許空字串（先 trim）。`qty!==1` → `bad_record`。缺任一營養素 → `bad_record`（沿用 `NUT_MSG`）。不建立 Items 列。
- `source` 省略：App 寫 `app`。Kyujin 的 `source` 必須是 `'kyujin'`，否則 `forbidden`（這條讓現有「Kyujin append 沒帶 source → forbidden」測試繼續過）。App 送 `source:'kyujin'` → `bad_record`。Kyujin 送 `quick` 或 `app` → `forbidden`。
- `store` 非空：Stores 裡要有這個 id（已刪除也可以，歷史店名還能顯示）。沒有這筆 → `bad_record`。
- 寫入成功且 `store` 非空：同一 lock 內 `last_eaten_at = max(原值, record.ts)`（字串比較即可，兩邊都是 `+08:00` 的 ISO）。
- 新欄位用現在的 `header_(sh).map(...)` 寫入，不要改回寫死欄序。

`updateLog_`：

- 允許的 patch 維持 `qty, grams, kcal, protein, fat, carb, ts, day, name`。不要允許改 `source`、`store`、`item_id`、`id`。patch 裡 `source` 若出現且和原值不同 → `bad_record`「不能改 source」。
- 列已 `deleted` → `{ ok:true, ignored:'deleted' }`，不寫。
- Kyujin：先找列。找不到，或 `source!=='kyujin'` → `forbidden`。找得到且 `source==='kyujin'` 才可改。App 可以改 `app`、`quick`、`kyujin` 三種 Log（畫面上它們長一樣）。
- 快速紀錄的 update 仍要 `qty===1`、`grams` 空、四項營養素合法。`name` 可以改成空的。

`softDelete`／`restore` Logs：

- App：維持現在，任何 Log 都可以。
- Kyujin：列存在且 `source==='kyujin'` 才允許。其餘 `forbidden`。Weights、Items、Stores、setConfig 對 Kyujin 維持 `forbidden`（Stores 見 §4.3）。

### 4.6 衝突

### 6.3 outbox 搬離 localStorage `app/src/api/index.ts`

現在佇列在 `foodlog.outbox`／`foodlog.failed`／`foodlog.cache`（localStorage 或測試傳入的 `Storage`）。改成只住在 `Kv`。

`createApi` 新增選項 `kv?: Kv`。`AppProps`、`useFoodLog` 把 `kv` 傳下去。生產環境不傳，內部用 IDB。測試要看佇列時傳 `memoryKv()`。

啟動遷移（`api.ready: Promise<void>`，`load`／`write`／`flush` 都先 await）：

1. 讀 localStorage（或傳入的 `storage`）的 `foodlog.outbox`、`foodlog.failed`、`foodlog.cache`。
2. IDB 的 `outbox` 是空的且 localStorage 有陣列 → 抄過去。兩邊都有 → 依 `qid` 取聯集，不要重複、不要丟任何一筆。`failed` 同樣處理。
3. `foodlog.cache` 若存在且 IDB `snapshot` 是空的 → 抄成 snapshot（補上 `day`：用 cache 裡 `serverTime` 的前 10 碼；沒有就用今天）。這是為了升級後第一次不要把已有使用者打回骨架。
4. 抄完立刻 `removeItem` 那三個 key。
5. 再啟動一次不可重複寫入。

`portion.test.tsx` 現在讀 `storage.getItem('foodlog.outbox')`。改成測試自己的 `memoryKv`：`JSON.parse(await kv.get('outbox') || '[]')`。離線那條仍要斷言第一筆是 `upsertItem`（`ov:`）、第二筆是 `append`。搜尋按鈕的 accessible name 會改，見 §10。

送出前把 `qid`、`queuedAt`、`groupId`、`label`、所有 `__` 欄從 body 刪掉。`groupId` 只用於「補營養素」的兩筆要同生共死：其中一筆永久失敗時，兩筆都進 `failed`，重試時仍依原順序先品項再紀錄。

重試間隔取代 `useFoodLog` 裡每 20 秒 `flush` 的那個 `setInterval`（AGENTS.md 第 5 條的「20 秒」改寫成下面這段；第 6 條橫幅不要動）：

- 暫時失敗後依序等 2 秒、5 秒、15 秒各自動 `flush` 一次。
- 三次之後停止計時，等 `visibilitychange` 變成 visible，或 `online` 事件，再試一次。
- 永久錯誤不進這個計時器。

`write()` 仍是先進佇列再 `flush`。畫面不等伺服器。

狀態：

| `__write` | 何時 | 畫面 |
|---|---|---|
| 無，且不在 outbox | 已同步 | 和現在一樣 |
| `pending` | 在 outbox | 數字立刻算進去。不滿 3 秒不要寫「待上傳」。`queuedAt` 起過 3000ms 才在該列第二行尾端加 muted「待上傳」 |
| `failed` | 永久錯誤，尚未捨棄 | 見 §7.9 |

`view()`＝伺服器快照（或上次成功的快照）深拷貝後，先套用 outbox，再套用未捨棄的 failed。合計用這份 view。`sumLogs` 不要因為 `__write` 就排除。

`read` 合併：

1. 伺服器資料換成新的 `lastData` 並寫入 snapshot。
2. 若某 id 在伺服器是 `deleted===true`，丟掉 outbox 裡對它的 `update`／`upsertItem`／`upsertStore`（刪除贏）。保留尚未送出的 `restore` 和全新 `append`（新 id）。
3. 再套用剩下的 outbox 與 failed。
4. 伺服器上已刪、本地 view 也刪的列，用 CSS 淡出，不要 `alert`。

樂觀更新 `last_eaten_at`：`applyOp` 在 `append` 且 `record.store` 非空時，把該店的 `last_eaten_at` 設成 `max(原值, record.ts)`。

樂觀刪店：`softDelete` `Stores` 時，把該店未刪除的品項一起 `deleted=true`，並設 `__cascade=店id`。尚未送出就復原：直接拿掉這筆 outbox，view 重算，品項回來。已經送出的復原：再排一筆 `restore`。

`emptySnapshot()` 不要再拿來當「讀取失敗的畫面資料」。讀取失敗且沒有快照：`lastData` 保持 `null`，讓 `loadState` 走 `error-empty`。不要把 `DEFAULT_CONFIG` 的 2000 塞進畫面。

`api.load()` 成功才寫 snapshot。失敗時若已有快照，保留快照並把錯誤丟給 hook，不要吞掉之後又畫預設值。現在的 `catch` 會落到 `emptySnapshot`，這條刪掉。

新增方法：

- `retryFailed(qid?: string)`：不傳則重排全部；傳了只重排那一筆（及同一個 `groupId`）。
- `discardFailed(qid: string)`：從 failed 移除，view 不再套用。Logs 的捨棄讓剩餘額度扣回。
- `dropQueued(qid: string)`：復原時若原寫入還在 pending，用這個拿掉，不要送反向請求。

待上傳的 3 秒標籤：`App` 在有 `pending` 時每秒 `setTick` 一次，傳給 `LogRow` 的 `now`。沒有 pending 就清掉 interval。

### 6.4 `loadState` `app/src/data/loadstate.ts`

純函式，方便測：

```ts
export type LoadState = 'skeleton' | 'cached-syncing' | 'fresh' | 'error-cached' | 'error-empty'
export type ErrorKind = 'offline' | 'server' | 'auth'

export function deriveLoadState(input: {
  booting: boolean          // IDB 還沒讀完
  cache: CachedSnapshot | null
  fresh: boolean            // 這次工作階段 read 已成功
  error: { kind: ErrorKind; code: string } | null
}): LoadState
```

- `booting` → `skeleton`（不要先畫 0）。
- 有 cache、尚未 fresh、沒有 error → `cached-syncing`。
- `fresh` 且沒有 error → `fresh`。
- error 且有 cache → `error-cached`。
- error 且沒有 cache → `error-empty`。

`errorKind`：

| 條件 | kind | 白話原因 | 代碼行 |
|---|---|---|---|
| `navigator.onLine===false` 或 `NetworkError` 且 kind 是 `fetch` | `offline` | 沒有網路連線 | `錯誤代碼 NET-0` |
| 逾時、`server_error`、`busy`、HTTP 5xx | `server` | 伺服器沒有回應，可能是暫時的問題 | `錯誤代碼 GAS-503`（用實際狀態碼；沒有狀態碼就用 `server_error`） |
| `error==='unauthorized'` | `auth` | 登入過期，請重新打開 | `錯誤代碼 unauthorized` |
| `error==='schema_outdated'` | `server` | 請先執行 migrateFoodLog | `錯誤代碼 schema_outdated` |

`useFoodLog` 回傳 `loadState`、`errorKind`、`errorCode`、`errorReason`、`staleToday`、`retrying`、`refresh`。

`staleToday`：cache 存在且 `cache.day !== taipeiToday(now)`。這時目標、品項、店家、歷史 Logs／Weights 仍給趨勢和品項頁；今天的剩餘卡和「今天的紀錄」改走骨架。不要把昨天的剩餘畫在今天。

換日：既有每分鐘 `setToday` 的 effect 保留。日期一變，若還沒有「今天」的成功 read，`staleToday` 變 true。

重試：

- 錯誤卡和 `SyncBadge` 的「重試」呼叫 `refresh()`。進行中按鈕文字「重試中…」並 `disabled`。
- 每次失敗只自動重試兩種事件各一次：回到前景、`online`。成功後把這兩個旗標清掉，下次失敗可以再各一次。
- `useFoodLog` 已經在 `online` 和 `visibilitychange` 時 `refresh`。不要再疊一個無條件的第二發。用 `inflight` 旗標把同時的 `refresh` 合成一個 Promise。

`SyncBadge` 的 300ms：進入 `cached-syncing` 時啟動計時。300ms 內變成 `fresh` 就不要把 badge 裝上。超過 300ms 仍在同步才顯示「同步中」。變成 `fresh` 後若 badge 出現過，改顯示「已同步」，1000ms 後以 250ms opacity 淡出並卸載。`prefers-reduced-motion` 時直接卸載，不要淡出、不要呼吸。

離線且有待送：badge 改成「離線 · N 筆待上傳」（muted 字，不是 `--destructive`），即使 `loadState==='fresh'` 也顯示。這條優先於「已同步」。`error-cached` 的「沒有同步 · 重試」優先於離線句。

### 6.5 禁止假數字

下面這些路徑在 `loadState` 是 `skeleton` 或 `error-empty`，以及 `staleToday` 時的「今天」區塊，都不要呼叫：

- `parseTargets(DEFAULT_CONFIG)` 或 `parseTargets({})` 之後拿去畫英雄數字。`parseTargets({})` 會得到 0，0 也不行。
- `RemainingSummary`、`MacroBar` 的目標／剩餘／「0 筆」。
- 「今天還沒有紀錄」（這句只有 fresh 或「今天的 cache 就是今天」且筆數真的是 0 才能出現）。
- 趨勢三格 KPI 的 `0`、假長條。資料真的不夠時，現有的「還沒有足夠的紀錄…」只在 `fresh` 或可用的歷史快取上出現。

`defaults.ts` 只留給後端預設和 `test/defaults.test.ts`。設定頁在 **有快照** 時可以顯示快照裡的 `target_kcal`，就算那個值恰好是 `2000` 也是真的設定，不是假數字。`loadstate.test.tsx` 的快照請把 `target_kcal` 設成 `1800`，這樣五個狀態的文字都不能包含 `2,000` 或 `2000`。

## 9. 邊界情況（要有測試或在流程裡走得到）

- 店名前後空白、中間空格、`・`、大小寫：norm 後相同就當同一家。
- 已刪除店家的名字可以再建。
- 刪店後復原：一起刪的品項回來；更早單獨刪的品項不回來；Logs 的數字與筆數不變。
- 刪店的同時有一筆尚未送出的「改品項」：read 之後刪除贏，改品項的 op 被丟掉。
- 對已刪列 update／upsert：`ignored:'deleted'`，前端不當失敗、不復活。
- 快速記錄 `qty:2` 或少一項營養素：GAS 與 mock 都 `bad_record`，畫面上不出現新列。
- 快速記錄品名空白：列表「快速記錄」／「1 筆」；編輯可補上名字。
- 舊 Log 沒有 `source` 欄：decode 成 `app`，第二行仍是來源與份量，不是「1 筆」。
- `upsertItem` 改營養素後，舊 Log 的 `kcal` 不變；新的一筆用新值。
- 快照 `day` 是昨天：今天英雄區是灰條；品項頁看得到店和品項；趨勢上週看得到；今天那一格不標 0 kcal。
- 300ms 內 read 成功：DOM 裡不要出現「同步中」。
- 沒有快照且 read 失敗：沒有 `2,000`、沒有 `0 筆`、沒有「今天還沒有紀錄」，有「讀不到今天的資料」和「重試」。
- 離線按「請 Kyujin 估算」：按鈕是「需要網路」，`adapter.calls` 長度不變。
- 遷移跑兩次：第二次空陣列，舊儲存格不變。
- 未 migrate 就打 `read`：`schema_outdated`，訊息「請先執行 migrateFoodLog」。
- localStorage 有兩筆 outbox、IDB 是空的：啟動後 IDB 有那兩筆且 `qid` 相同，localStorage 的 key 沒了。兩邊都有不同 `qid`：聯集。再啟動一次不會變四筆。
- 補營養素中途關 Sheet：outbox 仍是空的（既有測試，改讀 kv 之後要保持）。
- 高度 400px：dock 膠囊不在，搜尋 Sheet 裡仍有「常吃店家」。

5. `context.setOffline(true)`，記一筆，等 3200ms，看得到「待上傳」。`setOffline(false)`，等 flush，「待上傳」消失。
