## 0. 做完要長什麼樣子

手機 PWA（繁體中文、台北時間）。四個分頁：**今天 / 趨勢 / 品項 / 設定**。今天頁只做兩塊內容（剩餘額度、今日紀錄），右上一個體重圖示。搜尋框固定在今天頁底部。資料在 Brian 的 Google Sheet，經 Apps Script。前端有待送佇列。Kyujin 用同一個網址和密鑰，**只能新增或修改自建品項，以及寫體重**；不能寫飲食紀錄、不能補填官方品項、不能改設定。

每筆飲食紀錄的熱量、蛋白質、脂肪、碳水都是 ≥ 0 的有限數字。只有熱量的品項要先補三項營養素；面板關掉就什麼都不寫；後端拒收缺營養素的紀錄。

## 2. 品項快照

### 2.1 執行時的品項形狀

```ts
type CatalogItem = {
  id: string                 // "fm:1032099" 或 "711:" + sha1(name) 前 10 個 hex
  src: 'familymart' | '711' | 'custom'
  name: string
  cat: string
  serving: string            // 顯示用，例如 "1 份（100 g）" 或 "1 份"
  servingG: number | null    // null 就不能用克數記
  perPack: number            // 沒有就 1
  kcal: number               // 每份。缺熱量的品項不要收進快照
  protein: number | null     // null = 缺
  fat: number | null
  carb: number | null
}
```

營養素都是**每份**。`needsFill(item)` 為真的條件：`protein == null || fat == null || carb == null`。`0` 是完整，不是缺。

合併後給畫面的品項再加：`fav: boolean`、`createdBy: 'app' | 'kyujin' | null`、`override: boolean`、`needsFill: boolean`。

### 2.2 合併規則（`data/catalog.ts`）

1. 讀 `/catalog-v1.json`（相對於 vite `base`）。離線靠 SW 預快取。讀失敗就用空陣列，畫面不要崩潰。
2. Sheet `Items` 裡 `id` 以 `ov:` 開頭、`deleted !== true` 的列是補填。`base_id` 必須等於去掉 `ov:` 的官方 id。有補填就用那一列的 `kcal/protein/fat/carb/serving/serving_g` 蓋過快照，`needsFill` 變 false。**不改快照檔。**
3. `id` 以 `u:` 開頭且未刪除的列是自建品項，`src` 設 `'custom'`，`createdBy` 用欄位。
4. 官方收藏在 Config `fav_ids`（逗號分隔，去空白、去空字串）。自建收藏用該列的 `fav`。**收藏官方品項不要寫進 Items。**
5. 已刪除的 Items 列不要出現在搜尋裡。

| `familymart` | `全家` | 全家 |

### 2.4 `app/scripts/fetch-fam-details.mjs`（不要執行，也不要猜 API）

規格已經規定輸入輸出。腳本只做這些事：

```
node app/scripts/fetch-fam-details.mjs \
  --input <fam_all.json> \
  --output <fam_details.jsonl>
```

- 預設路徑可以是 `/workspace/food-research/fam_all.json` 和 `/workspace/food-research/fam_details.jsonl`，但不要為了寫這個腳本去打開那個目錄。
- `fam_all.json` 不是陣列，結構是 `{LIST:[{CATEGORY_NAME, ITEM:[…]}]}`：要先攤平，把外層的 `CATEGORY_NAME` 帶進每個 ITEM。每筆只用 `CMNO`、`PRODNAME`、`NOTE`、`CATEGORY_NAME`。測試的示意檔也要用這個巢狀結構。
- 環境變數 `FAM_ITEM_URL` 未設定：印「尚未設定 FAM_ITEM_URL，不打網路」，**exit 0**。不要寫死任何全家網址、host、query string。
- 有設定時，URL 裡的 `{cmno}` 換成該筆 `CMNO`。每個請求間隔至少 500 ms（每秒最多 2 次）。逾時 20 秒。
- 可續跑：輸出 jsonl 裡已經有的 `cmno` 跳過。
- HTTP 失敗或 JSON 解析失敗：該筆不寫、印一行 stderr、繼續。這種品項最後會變成「要補營養素」。
- HTTP 成功：寫一行 JSON，欄位固定為：

```json
{"cmno":"1032099","name":"法式香草嫩雞胸","cat":"小菜、滷味、湯品","note":"每份熱量 106 大卡;每份規格 100 公克;(本包裝含 1 份)","kcal":106,"protein":20.8,"fat":1.5,"carb":2.3}
```

- `name`/`cat` 用列表那筆，不用回應裡的名字。
- 營養素只讀 `NUTRIENTS[0].PROTEIN`、`TOTALFAT`、`CARBOHYDRATE`。缺就寫 `null`。`kcal` 能從 `NOTE` 解析就寫數字，否則 `null`。
- 實作者不要執行這個腳本，CI 也不要跑。

`NOTE` 解析（列表和明細都用同一函式）：

- `每份熱量 106 大卡` 或 `熱量 106 大卡` → kcal = 106
- `每份規格 100 公克` → servingG = 100；沒有這段 → `null`
- `本包裝含 2 份` → perPack = 2；沒有 → 1
- 有 servingG 時顯示 `1 份（100 g）`，否則 `1 份`

### 2.5 `app/scripts/build-catalog.mjs`

```
node app/scripts/build-catalog.mjs \
  --fam-list <fam_all.json> \
  --fam-details <fam_details.jsonl> \
  --seven-dir <放 711_0.xml … 711_21.xml 的目錄> \
  --out app/public/catalog-v1.json
```

- 全家：以 `fam_all.json` 為全集，用 `cmno` 左連 `fam_details.jsonl`。有明細且四項都是數字 → 完整品項。沒有明細，或蛋白/脂肪/碳水缺漏：若列表 `NOTE` 解析得出 kcal，就收進快照且三項為 `null`（要補營養素）；連 kcal 都沒有就跳過。id = `fm:` + `CMNO`。`cat` 用 `CATEGORY_NAME`。
- 7-11：依序讀 `711_0.xml` … `711_21.xml`。缺檔就警告並跳過。每個 `<Item>` 讀 `name`、`kcal`、`content`。`kcal` 空白或不是有限數字 → **不收**。`price` 忽略。`cat` 固定 `"鮮食"`。`serving` = `"1 份"`，`servingG` = `null`，`perPack` = 1，三項營養素 `null`。id = `711:` + SHA1(UTF-8 品名) 的 hex 前 10 碼（`node:crypto` `createHash('sha1')`）。同名只留檔案順序中的第一筆。
- 輸出 `{ "version": "2026-10-10", "items": [ ... ] }`，依 `id` 排序，數字不要用字串。
- 來源目錄不存在：exit 1，訊息寫清楚，**不要編造品項**。
- `npm test` 和 `npm run build` 不得呼叫這個腳本，也不得要求 `/workspace/food-research` 存在。
- 解析器另用 `app/test/fixtures/catalog-src/` 裡的小檔測（一個含 2 筆的假 json、一行 jsonl、一個只有兩個 `<Item>` 的 xml，其中一筆 kcal 空白）。

## 3. Sheet 與 Apps Script

### 3.1 要不要重新部署

這是**新後端**，沒有舊的 food-log 分頁可以沿用。

- Brian 必須新部署一次，否則 App 沒有後端。步驟在 §12。
- 只要改了 `app/gas/*.gs`（含 `Trends.gs`），前端部署**不會**更新後端。Brian 要在 Apps Script「管理部署作業 → 編輯 → 新版本」再部署，網址才會吃到新程式。`/exec` 網址維持不變。
- 只改 `app/src` 或靜態檔：不用重部署 Apps Script。
- 欄位名稱和順序一旦上線就不能改、不能插入中間。以後只能加在該列最後。這次就把 §3.2 的順序寫死。
- `setupFoodLog` 對已存在的分頁只補缺少的表頭（加在最後），不覆蓋已有 Config，不清資料。

food-log **沒有照片**，`appsscript.json` 不要 Drive 範圍，`Setup.gs` 不要建立雲端硬碟資料夾，也不要 `PARTNER_EMAIL`。

### 3.2 分頁與欄位（順序固定）

共同規則：人看得懂的值。布林寫 `TRUE` / `FALSE`。時間是含 `+08:00` 的 ISO 字串。空的選填數字寫空字串，讀回來變成 `null`。

**Items**（主鍵 `id`）

`id`, `ts`, `deleted`, `updated_at`, `kind`, `base_id`, `src`, `name`, `serving`, `serving_g`, `kcal`, `protein`, `fat`, `carb`, `fav`, `created_by`

- `kind`：`自建` 或 `補填`
- `id`：自建 `u:<uuid>`；補填 `ov:<官方 id>`，且 `base_id` = 那個官方 id
- `src`：`7-11`／`全家`／`其他`
- `created_by`：`app` 或 `kyujin`
- `fav`：只有自建品項使用。官方收藏不在這張表

**Logs**（主鍵 `id`）

`id`, `ts`, `deleted`, `updated_at`, `day`, `item_id`, `name`, `src`, `qty`, `grams`, `kcal`, `protein`, `fat`, `carb`

- `ts` 是吃的時間。`day` 是台北日期 `YYYY-MM-DD`，由前端算好
- `name` 是當下的品名快照
- `kcal/protein/fat/carb` 是**這筆實際吃的量**（已換算、已四捨五入），不是每份
- 用份數時 `grams` 空著。用克數時 `grams` 有值，`qty` = `grams / servingG`
- 沒有 `who` 欄。不要從西西里抄 `who`

**Weights**（主鍵 `day`，不是 `id`）

`day`, `ts`, `deleted`, `updated_at`, `kg`, `id`

一天最多一筆未刪除的列。`id` 仍由前端產生，放在最後一欄，用來做冪等。

**Config**（主鍵 `key`）

`key`, `value`, `updated_at`

預設（`defaults.ts` 和 `Schema.gs` 的 `DEFAULT_CONFIG` 必須完全一致，值都是字串）：

| key | value |
|---|---|
| `target_kcal` | `2000` |
| `target_protein` | `150` |
| `target_fat` | `60` |
| `target_carb` | `200` |
| `tdee` | 空字串 |
| `remind_meal_times` | 空字串 |
| `remind_weight_time` | 空字串 |
| `fav_ids` | 空字串 |

`theme` **不要**進 Sheet，只放 localStorage `foodlog.theme`。

`setConfig` 只接受上表這些 key。其他 key（含 `theme`）回 `bad_record`。

### 3.3 寫入語意

所有寫入包 `LockService.getScriptLock().tryLock(10000)`。拿不到回 `{ ok:false, error:'busy', message:'另一個人正在寫入，請再試一次' }`。讀取不加鎖。`updated_at` 一律由後端寫成台北現在時間，不信任客戶端。

錯誤碼只有這些：`unauthorized`、`bad_json`、`bad_action`、`bad_table`、`bad_record`、`not_found`、`busy`、`server_error`、`forbidden`。

密鑰比對照 sicily：長度不同直接失敗，再逐字元 XOR，避免提早返回。密鑰只在 Script Properties 的 `SHARED_SECRET`。

`client`：Kyujin 送 `"kyujin"`。App 不送或送 `"app"`。其他值當一般 App，不給予額外權限。

#### 營養素驗證（Logs 的 append/update，以及 upsertItem）

四個欄位都要是有限數字且 ≥ 0。`null`、空字串、`NaN`、負數、Infinity、數字字串都回 `bad_record`，訊息「紀錄必須有熱量、蛋白質、脂肪、碳水」。`0` 可以。不要在後端依 `item_id` 重算；Kyujin 和 App 都直接加總 Logs 上已經存好的數字。

#### append Logs

- 只有 `table:'Logs'`。其他表回 `bad_table`。
- 必填：`id`、`ts`、`day`、`item_id`、`name`、`src`、`qty`，加上四項營養素。
- `qty` 是有限數字且 > 0。`grams` 省略、空字串，或有限數字且 > 0。
- `src` 只能是 `7-11`／`全家`／`其他`。
- `day` 必須等於 `taipeiDay(ts)`（算法同 §4，不要用會受機器時區影響的 `getDate()`）。不相等回 `bad_record`。
- `day` 不能晚於台北今天。
- 已經有相同 `id`：回 `{ ok:true, duplicate:true, record }`，不要再 append。
- `client:"kyujin"`：直接 `forbidden`，訊息「Kyujin 只能寫入自建品項或體重」。

#### update Logs

- 可改 `qty`、`grams`、`kcal`、`protein`、`fat`、`carb`、`ts`、`day`、`name`。不能改 `id`。
- 用合併後的整列再跑一次四項營養素和 `day === taipeiDay(ts)`。
- 找不到 id：`not_found`。
- Kyujin：`forbidden`。

#### softDelete / restore

- `{ table:'Logs'|'Weights'|'Items', id }`。
- Logs、Items 依 `id`。Weights 也依列上的 `id`（不是依 day）。
- 軟刪除設 `deleted=TRUE`。restore 設 `deleted=FALSE`。
- Weights restore 時，若該 `day` 已經有另一筆未刪除的列，回 `bad_record`「這天已經有一筆體重」，避免一天兩筆。
- Kyujin 對 Logs、Items 的 softDelete/restore：`forbidden`。Kyujin 不需要刪體重；也回 `forbidden`。

#### upsertItem

- `id` 以 `fm:` 或 `711:` 開頭：兩個客戶端都 `forbidden`（不能改官方列）。
- `ov:`：`kind` 必須是 `補填`，`base_id` 必須等於 `id.slice(3)`，`created_by` 必須是 `app`。Kyujin 呼叫：`forbidden`。
- `u:`：`kind` 必須是 `自建`，`base_id` 空。
- 其他 id：`bad_record`。
- `name`、`serving` 非空字串。`serving_g` 空或 > 0。四項營養素通過上面的驗證。`src` 三選一。`fav` 布林。
- Kyujin 額外限制：`id` 必須 `u:` 開頭，`created_by` 必須是 `kyujin`。若該 id 已存在且 `created_by` 不是 `kyujin`（Brian 自己建的），`forbidden`。Kyujin 不能改 `ov:`，也不能改官方 id。
- App 可以改 Kyujin 建的 `u:` 品項（PRD：自建品項都能在 App 裡改）。若現有列的 `created_by` 是 `kyujin`，後端強制保持 `kyujin`，不要被 App 改成 `app`（標籤才不會消失）。
- 同一 `id` 再送一次：更新該列，回 `{ ok:true }`，不要插第二列。

#### upsertWeight `{ day, kg, id, ts }`

範圍：`kg` 30.0–250.0，最多一位小數（`Math.round(kg * 10) / 10` 後必須等於原值，否則 `bad_record`）。`day` 不能晚於台北今天。`ts` 必填。`day` 必須等於 `taipeiDay(ts)`。

演算法，順序不要改：

1. 若任一列（含已刪除）的 `id` 等於這次的 `id`：回 `{ ok:true, duplicate:true, record }`，**不要改儲存格**。這是重送。
2. 否則若有該 `day` 且未刪除的列：只覆寫 `kg`、`ts`、`updated_at`。**不要改 `id`，不要改 `day`。** 回 `{ ok:true, overwritten:true, record }`。
3. 否則 append 新列。

因此：同一天第二筆記錄（新的 id）會蓋掉公斤數，Sheet 仍只有一筆未刪除的列。較早那次請求若晚到（舊 id），步驟 1 直接成功，不會把公斤數改回去。

復原：

- 這次是新 append 的：前端 softDelete 那個 `id`。
- 這次是覆寫的：前端記住舊的 `kg`，再送一次 `upsertWeight`，用**新的 id** 和舊的 `kg`。不要重用舊 id，否則步驟 1 會把它當成重送而不寫回。

#### setConfig

Kyujin：`forbidden`。`fav_ids` 是逗號分隔字串，後端不檢查 id 在不在。`tdee` 允許空字串。有值時必須是整數字串，數值 1200–5000，否則 `bad_record`。四個目標：熱量是 ≥ 0 的整數字串；蛋白、脂肪、碳水是 ≥ 0 的數字字串。提醒時間允許空字串，或 `HH:MM` 以逗號相接（餐點）、單一 `HH:MM`（體重）。格式不對回 `bad_record`。

## 4. 日界線（`lib/day.ts`）

```ts
const OFFSET = 8 * 3600 * 1000
export function taipeiDay(date: Date): string {
  return new Date(date.getTime() + OFFSET).toISOString().slice(0, 10)
}
export function taipeiIso(ms: number): string {
  return new Date(ms + OFFSET).toISOString().slice(0, 19) + '+08:00'
}
```

禁止用 `getFullYear()` / `getDate()` / `toLocaleString()` / `Intl` 時區。`YYYY-MM-DD` 加減天用 `Date.parse(day + 'T00:00:00Z')` 再加 86400000，再 `toISOString().slice(0, 10)`。

`weekStart(day)`：把該日的 UTC 星期換算成往回走到週一。星期日減 6 天，星期一減 0 天。`weekStart('2026-10-10') === '2026-10-05'`。`weekStart('2026-10-11') === '2026-10-05'`。`weekStart('2026-10-12') === '2026-10-12'`。`weekStart('2026-10-01') === '2026-09-28'`。

後端用同一條 OFFSET 公式，不要用 `Utilities.formatDate` 做驗收比對（測試機器的時區可能是 UTC 或洛杉磯）。

已知瞬間（測試要寫死）：

- `2026-10-10T15:59:59.000Z` → 台北日 `2026-10-10`
- `2026-10-10T16:00:00.000Z` → 台北日 `2026-10-11`

`npm test` 在 `TZ=UTC` 和 `TZ=America/Los_Angeles` 都要過。實作若寫對，不需要在測試裡改 process 時區也會過；仍然不要呼叫會看本地時區的 API。

## 5. 營養與趨勢純函式

### 5.1 `lib/nutrition.ts`

```ts
roundKcal = (n) => Math.round(n)          // 只有 ≥ 0 的數會進來
roundMacro = (n) => Math.round(n * 10) / 10
```

**存檔時才四捨五入。** 畫面合計用存檔值相加，不要把原始乘積再加一次。

- 份數：`qty` 為正數。按鈕是 0.5、1、1.5、2。營養素 = 每份 × qty，再 round。
- 克數：品項沒有 `servingG` 就不能走這條。`qtyStored = grams / servingG`。營養素 = 每份 × grams / servingG，再 round。
- 預設份量：這個 `item_id` 最後一筆未刪除 Log。若那筆 `grams` 有值就開克數模式並帶克數；否則帶 `qty`，沒有歷史就 1 份。

範例（每份 106 kcal、蛋白 20.8、脂肪 1.5、碳水 2.3、servingG 100）：

| 輸入 | 存檔 |
|---|---|
| 1.5 份 | kcal 159，蛋白 31.2，脂肪 2.3，碳水 3.5 |
| 50 g | qty 0.5，kcal 53，蛋白 10.4，脂肪 0.8，碳水 1.2 |
| 30 g | qty 0.3，kcal 32，蛋白 6.2，脂肪 0.5，碳水 0.7 |

`sumLogs(logs)`：忽略 `deleted`。回 `{ kcal, protein, fat, carb, count }`，kcal 用整數和，營養素用已存的一位小數相加（不要再 round 總和，除非總和出現二元浮點垃圾；先以「整數分」相加：蛋白用十分之一克的整數）。

`remaining(targets, totals)`：`target - total`。負數留給格式化，函式本身可以回負數。

`formatRemain(n, unit)`：

- n ≥ 0：熱量整數（千分位）、營養素一位小數，加上單位，例如 `900 kcal`、`75.0 g`
- n < 0：`超過 ${abs} kcal` 或 `超過 ${abs} g`，不要負號、不要「爆了」

數字和單位之間有一個半形空格。中文和數字之間也有一個半形空格。標點用全形。

編輯紀錄時：若合併後的品項還在，用**現在的每份營養素 × 新份量**再 round（補填之後再改舊紀錄，以補填後的每份為準）。品項已經不在目錄：用 `新qty / 舊qty` 縮放這筆已存的四個數字再 round。

### 5.2 不完整的日子

輸入：某日的 `count`、`kcal`、`targetKcal`、該日、`today`。

不完整 ⇔ `day < today` 且（`count ≤ 1` 或 `kcal < 0.5 × targetKcal`）。

- `count = 0` 也是不完整。
- **今天永不算不完整**，就算 0 筆或熱量很低。
- 邊界用存檔熱量合計：目標 2000 時，`kcal < 1000` 才因熱量不完整。1000 且 `count ≥ 2` 是完整。999 不完整。1000 但 `count = 1` 仍不完整（筆數規則先成立）。
- 未來的日子不進統計。

### 5.3 `weekSummary(logs, config, today, weekMonday)`

只看 `weekMonday` … `weekMonday+6` 且 `day ≤ today`。

- **平均攝取**：這些日子裡完整日的 kcal 平均，顯示時 `Math.round`。沒有完整日 → `null`（畫面「—」）。
- **平均赤字**：`tdee` 空 → `null`（畫面不顯示數字，改灰字「先到設定填每日消耗，就能看到赤字」）。否則 `tdee - 上面那個四捨五入後的平均`。負的由畫面寫「平均超過 X kcal/天」。
- **蛋白質達標**：分子 = 已到的日子（含今天、含不完整日）中 `protein ≥ target_protein` 的天數。分母 = 已到的天數，不是固定 7。本週六（2026-10-10）是 `n/6`，不是 `n/7`。週日還沒到就不進分母。
- **不完整天數 N**：該週裡 `day < today` 且不完整的天數。N > 0 才顯示「不含記錄不完整的 N 天」。不完整日不進平均，**但進蛋白質的分母**。

### 5.4 四週熱量長條

`chartStart = addDays(weekStart(today), -21)`，連續 28 天，到本週週日。本週還沒到的日子 `slot = 'future'`（不畫長條，也不要標不完整）。`day === today` 的 slot = `'today'`（50% 不透明度，標「今天」），即使 0 筆或低熱量也**不是**不完整。更早的日子用 §5.2。

超過目標的長條**不要**改成 `--over`。不完整才改斜線。

### 5.5 體重

未刪除、一天一筆。若資料裡同一天有多筆未刪除（不該發生），取 `updated_at` 較新的那筆。

7 日平均：以日 d 為終點的 `[d-6, d]` 內，有體重的天數 ≥ 3 才有值，算術平均。否則 `null`。

預期線：

- `tdee` 空 → 不產生序列（畫面不畫）。
- 起點日 = `addDays(today, -28)`。若該日沒有 7 日平均，就往後一天天找，直到有值。都沒有就沒有預期線。
- `expected[起點] = 該日 7 日平均`（還沒扣赤字）。
- 其後每一天 d，直到**昨天**為止：`expected[d] = expected[d-1] - deficit(d) / 7700`。
- `deficit(d)`：該日完整 → `tdee - kcal(d)`；該日不完整 → `tdee - target_kcal`。
- **今天不加這一步。**
- 文字「4 週少了／多了」：終點用今天的 7 日平均，沒有就用今天以前最後一個有 7 日平均的日子。差值 = 終點 − 起點。顯示四捨五入到 1 位小數。負的說「少了」，正的說「多了」，0.0 說「沒有變化」。不要正負號。
- 灰字「依赤字預期少 1.1 kg，實際少 0.9 kg」：預期差值 = 預期線最後一點 − 起點；實際差值用上一則。同樣用少了／多了。

完整日少於 3 天（以這 28 天窗口計）：熱量圖和三格摘要改顯示「還沒有足夠的紀錄，記滿 3 天就會出現趨勢。」有體重就仍畫體重卡；完全沒有體重就連體重卡也隱藏。

### 5.6 與 Apps Script 對齊

`app/test/fixtures/trends-cases.json` 放輸入和期望輸出。`lib/trends.ts` 和 `gas/Trends.gs` 都吃同一份。`trends-parity.test.ts` 用 gas-fakes 呼叫 `weekSummary_` / `weightSeries_`，和 TS 的結果比對。顯示用的 kcal 差必須是 0；公斤序列允許絕對誤差 < 1e-6，顯示到小數一位必須相同。

改一邊的演算法必須改另一邊。兩個檔案頂端都寫這句。

`Trends.gs` 不要複製一份「差不多」的公式。蛋白質分母、50% 用 `<` 不是 `≤`、今天不算不完整、不完整日的預期赤字用 `tdee - target`，這四點最容易寫錯。

## 6. 搜尋（`data/search.ts`）

啟動後在 `requestIdleCallback`（沒有就 `setTimeout(0)`）建索引，不要擋住第一次繪製。不要為了 v1 加 Web Worker，除非 idle callback 仍讓你做不到 p95。每項索引文字：

`norm(品牌前綴 + name + cat)`。品牌前綴：全家品項加 `全家`，7-11 加 `711` 和 `7-11`，自建加 `自建`。

`norm`：`String.normalize('NFKC')`、轉小寫、去掉所有空白、去掉 `-`、`·`、`・`、`（）`、`()`、`【】`、`[]`、`、，。．/／`。

查詢也做 `norm`。空字串不走計分（見下方空查詢）。

計分取**一種**最好的，不要把三種加在一起：

1. 索引包含整段查詢：100。出現在開頭再 +20。
2. 否則查詢每個字依序出現（子序列，「雞肉」可以中「雞胸肉」；順序不對不算）：60。
3. 否則查詢長度 ≥ 3：query 的字元 bigram（重疊的兩兩）有多少比例出現在索引 bigram 裡。比例 = 命中的 query bigram 數 / query bigram 數。比例 ≥ 0.5 才入選，分數 = `40 × 比例`。

再加權（可疊加）：收藏 +50；最近 14 天（含今天，以台北日）吃過 +30，每多 1 次再 +2，這段最多再 +20（所以次數加權上限 +20，不是無限）；自建 +10。

取分數 > 0 的前 50 名。同分用品名字串排序。

篩選膠囊在計分前過濾：

- 全部：不過濾
- 收藏：`fav`
- 7-11：快照 src `711`（自建即使來源選了 7-11 也不進這個膠囊；自建只出現在全部，以及被收藏時的收藏）
- 全家：快照 src `familymart`，同樣不含自建

分組（有打字時）：

- 前組標題「收藏・最近吃過」：收藏、或 14 天內吃過、或自建

## 7. 畫面（DESIGN v0.4）

全部用 token。不要寫死 `#D4F36A` 這類色碼在元件裡（圖表的 SVG `stroke="var(--chart-goal)"` 可以）。不要漸層插畫、不要表情符號、不要西西里的溫暖配色。字級用 token 的 `text-hero` / `text-2xl` / `text-xl` / `text-lg` / `text-base`。所有數字加 `tabular-nums`（class `tnum`）。點擊區至少 44。相鄰可點元件間距至少 8。頁面左右 16。正文字不小於 16px。輸入 `font-size: max(16px, 1em)`，tokens.css 已經有。

預設深色。`<html class="light">` 才是淺色。不要跟著系統配色。切換時把 `meta[name=theme-color]` 改成 `#0B0B0C` 或 `#F5F5F3`。

減少動態：tokens.css 已把動畫壓到 1 ms。進度條用 `transform: scaleX`，不要動畫 `width`。Sheet 用 350 ms、`var(--ease-spring)`；`prefers-reduced-motion` 時只淡入。不要呼叫 `navigator.vibrate`。

焦點：打開 Sheet 把焦點放進 Sheet。搜尋 Sheet 放進搜尋框（必須和點擊同一個同步事件，iOS 才會出鍵盤）。份量 Sheet 放上「記錄」按鈕，**不要**自動聚焦任何輸入框。補營養素步驟沒有「記錄」，焦點放在 Sheet 容器，不要放進數字欄。關掉後焦點回到觸發的按鈕。焦點框 2px `var(--ring)`。

## 8. 前端資料層細節

`createApi` 照 sicily 的 outbox：先寫 localStorage，依序 flush，網路錯誤停住並留在佇列，`busy` 和 `server_error` 留在佇列，永久錯誤（含 `forbidden`、`bad_record`）移到 failed 並繼續下一筆。樂觀更新用同一套 `applyOp`。

寫入 action：`append`、`update`、`softDelete`、`restore`、`upsertItem`、`upsertWeight`、`setConfig`。`read`、`history`、`summary`、`trends` 不進佇列。App 本身可以不呼叫 `summary` / `trends`（畫面用本機純函式算）。Kyujin 才打這兩個 action。

`applyOp` 要認得 `upsertWeight`：同一天未刪除的體重被新數字蓋掉，並記住它是覆寫還是新增，復原才做得對。`upsertItem` 依 id 取代或插入。

快取的 snapshot 形狀和 `read` 的成功回應相同。第一次就離線：用快取；沒有快取就用 `defaults` 的目標和空陣列。

`gas.ts` 的失敗訊息沿用 sicily 的中文。逾時 `kind:'timeout'`。HTTP 非 2xx 是 `NetworkError`，不是 `ServerError`。回應不是 JSON：`{ ok:false, error:'bad_response', message:'回應不是 JSON：請確認 Apps Script 部署設成「任何人」可存取' }`。

mock adapter 要實作和後端一樣的拒收（缺營養素、Kyujin forbidden、同日體重覆寫、重複 id）。測試才不用連 Google。
