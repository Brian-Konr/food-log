## 0. 假 Apps Script（先改，不然新測試測不到）

檔案：`test/gas-fakes.ts`。真的試算表會把未設純文字的 `'7-11'` 和 `'YYYY-MM-DD'` 轉成 Date。現在的 fake 只把 ISO 時間和 `'TRUE'`／`'FALSE'`／數字字串轉掉，所以現有測試看不出這個 bug。

`FakeSheet` 補上：

- `getName()` 回傳 `this.name`。
- `maxRows = 1000`，`getMaxRows()` 回傳它。
- `formats = new Map()`，key 是 `` `${row}:${col}` ``（1-based，和現有 `textCells` 一樣）。
- `setNumberFormat(f)` 必須套到這個 range 的**每一格**，不能只標左上角。`f === '@'` 時把那些 key 放進 `textCells` 並 `formats.set(key, '@')`；其他格式就從 `textCells` 刪掉並記下格式。仍 `return range`，讓 `.setNumberFormat('@').setValue(v)` 可以串。
- `setValues` 每一格呼叫 `set(row, col, value)`。`set` 在 `textCells` 有該格時存原值，否則走 `sheetCoerce`。
- `sheetCoerce` 在現有規則之前加兩條（只在該格不是純文字時）：
  - 字串 `'7-11'` → `new VmDate(Date.UTC(taipeiYear, 6, 11))`。`taipeiYear` 用 `new Date(Date.now() + 8*3600*1000).getUTCFullYear()`。這是 UTC 午夜 7 月 11 日，`taipeiIso_` 會變成 `YYYY-07-11T08:00:00+08:00`，和 Kyujin 看到的字串同一種。
  - `/^\d{4}-\d{2}-\d{2}$/` → `new VmDate(v + 'T00:00:00Z')`。`taipeiIso_` 會變成 `YYYY-MM-DDT08:00:00+08:00`。
- 用 vm 裡的 `Date`（檔案裡已有的 `VmDate`）。GAS 的 `normalizeCell_` 若改用 `Object.prototype.toString.call(v) === '[object Date]'`，Node Date 和 VmDate 都認得出來。測試仍不要把自己 `new Date()` 的假設寫死成年份；斷言用「讀回來是 `7-11`」和「`day` 是 `YYYY-MM-DD`」。

`appendRow` 維持「整列 `sheetCoerce`、不設 `@`」。新的寫入路徑不再呼叫它。測試要種一筆「已被轉成 Date」的舊資料時，用 `appendRow`，不要用修好的 `writeRow_`。

## 2. 寫入 helper（`gas/Code.gs`）

新增兩個函式（放在 `toCell_` 附近）：

```javascript
function isTextCol_(table, col) {
  var list = TEXT_COLS[table] || [];
  return list.indexOf(col) >= 0;
}

/** 先把文字欄設成 @，再 setValues。不要對整列 setNumberFormat('@')，否則 kcal 會變成文字，nutritionOk_ 的 typeof number 會失敗。 */
function writeRow_(sh, rowIndex, cols, values) {
  var table = sh.getName();
  var i;
  for (i = 0; i < cols.length; i++) {
    if (isTextCol_(table, cols[i])) sh.getRange(rowIndex, i + 1).setNumberFormat('@');
  }
  sh.getRange(rowIndex, 1, 1, cols.length).setValues([values]);
}

function writeCell_(sh, rowIndex, colIndex, colName, value) {
  var range = sh.getRange(rowIndex, colIndex);
  if (isTextCol_(sh.getName(), colName)) range.setNumberFormat('@');
  range.setValue(value);
}
```

順序一定是先 `@` 再寫值。先 `setValue` 再補格式，試算表已經把 `'7-11'` 收成 Date，補格式不會變回 `7-11`。

新列的列號：`var rowIndex = sh.getLastRow() + 1`（在既有的 `withLock_` 裡面）。用 `writeRow_(sh, rowIndex, cols, row)` **取代** `sh.appendRow(row)`。

## 3. 依欄位讀取（`gas/Code.gs` 的 `rows_`／`normalizeCell_`）

`rows_` 現在是 `normalizeCell_(values[r][c])`。改成傳欄名：

```javascript
obj[header[c]] = normalizeCell_(values[r][c], String(header[c] || ''));
```

`normalizeCell_` 改成知道欄名。日期判斷用 `Object.prototype.toString.call(v) === '[object Date]'`，不要用 `instanceof`（跨 realm 會漏）。台北日仍用現有的 `taipeiDay_`（`Date` + 8 小時再 `toISOString` slice）。不要用 `getMonth()`／`getDate()`／`Intl`。

```javascript
function isDate_(v) {
  return Object.prototype.toString.call(v) === '[object Date]';
}

function normalizeCell_(v, col) {
  col = col || '';
  if (col === 'src') {
    if (isDate_(v)) return taipeiDay_(v).slice(5, 10) === '07-11' ? '7-11' : taipeiIso_(v.getTime());
    if (typeof v === 'string' && /^\d{4}-07-11(?:$|T)/.test(v)) return '7-11';
    return v;
  }
  if (col === 'day') {
    if (isDate_(v)) return taipeiDay_(v);
    if (typeof v === 'string' && /^\d{4}-\d{2}-\d{2}/.test(v)) return v.slice(0, 10);
    return v;
  }
  if ((col === 'ts' || col === 'updated_at' || col === 'last_eaten_at') && isDate_(v)) {
    return taipeiIso_(v.getTime());
  }
  if (isDate_(v)) return taipeiIso_(v.getTime());
  return v;
}
```

規則：

- `day` 的 Date → `YYYY-MM-DD`（`taipeiDay_`）。UTC 午夜的 `2026-10-12` 讀成 `2026-10-12`，不是 `2026-10-12T08:00:00+08:00`。
- `ts`／`updated_at`／`last_eaten_at` 的 Date → 既有的 `taipeiIso_`（`YYYY-MM-DDTHH:mm:ss+08:00`）。不要收成純日期。
- `src` 的 Date，且台北曆的月日是 07-11（**任何年**，含 2026 和 2027）→ `'7-11'`。不是 7 月 11 日的 Date 仍走舊的 ISO，不要猜成 `7-11`。
- `src` 已經是字串 `2026-07-11` 或 `2026-07-11T08:00:00+08:00` → `'7-11'`。`2026-11-07...`（11 月 7 日）不要轉。`全家`、`其他`、`''` 原樣。
- 其他欄位維持舊行為：Date → ISO，其餘原樣。
- `configValueToString_` 不要改（提醒時間 `HH:mm` 仍走那裡）。

這樣 `updateLog_` 在 patch **沒有** `day` 時，`merged.day` 已是 `YYYY-MM-DD`，`String(merged.day) !== taipeiDay_(merged.ts)` 不會再因為儲存格是 Date 而失敗。有帶 `day` 的更新也要寫回純文字（上一節的 `writeCell_`）。

## 4. Setup 整欄格式與遷移（`gas/Setup.gs`）

`formatColText_` 改成格式化**整欄**，含表頭和還沒資料的列：

`ensureFoodLogSheets_`：每次執行（不是只有新建分頁或新欄）都對該分頁 `TEXT_COLS` 裡、表頭已存在的欄呼叫 `formatColText_`。Items、Logs、Stores、Weights 都要。只 `setNumberFormat`，**不要**在這裡改儲存格的值（`gas-migrate.test.ts` 的「舊儲存格不動」靠這個）。Stores 現在只在新建時格式化整表，那個特例改成大家走同一條 `TEXT_COLS`。

2. 依表頭把 `TEXT_COLS` 整欄 `formatColText_`。
3. `getDataRange().getValues()`，從第 2 列開始（不要算表頭）。
4. 欄是 `day` 且值是 Date → `writeCell_` 寫入 `taipeiDay_(v)`，筆數 +1。
5. 欄是 `day` 且值是字串、符合 `/^\d{4}-\d{2}-\d{2}T/` → 寫入 `slice(0, 10)`，筆數 +1。已經是 `YYYY-MM-DD` 的不要算。
